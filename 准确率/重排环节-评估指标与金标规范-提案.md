# 重排环节（ranking.ts）· 评估指标体系与金标规范 · 提案（2026-07-15）

> 角色：metric-designer。目标：为「相关性重排」环节定义一套**可复现、产品对齐、能反哺 prompt** 的评估指标，并给出配套金标规范。对标已完成的萃取环节评估（金标 v2 + `run-extraction.ts` + 收尾档案）。
> **决策已拍板（2026-07-15）**：见第 7 节。方向确认进 P0/P1，据此开写 `run-ranking-score.ts` 与 `--blind` 标注变体。

---

## 0. 背景与现状（这一环节现在有什么、缺什么）

**被评对象**：`src/services/ranking.ts` 的 `rankQuestions(story, candidates) → RelevanceScore[]`。用 qwen-plus 对召回来的候选题按「故事贴合度」打 0–100 分并降序，`reason` 一句话。

**产品消费方式**（`matching.ts` + `constants.ts`，指标必须围绕它设计）：
- 分数决定**用户看到什么**，四档展示：
  - **首屏 高匹配** `≥85`（第一眼看到，第一印象）
  - **折叠 中匹配** `60–84`（"查看更多"）
  - **折叠 低匹配** `40–59`（"查看更多"）
  - **隐藏** `<40`（不展示、不入库，用户永远看不到）
- 重排降级（返回空）时回退漏斗序，候选标 `unscored`，仍按可见区展示。

**已建**：`scripts/eval/run-ranking.ts` —— 跑**真实线上全链路** `matchByStory`（萃取→三层召回漏斗→重排），把每条故事的候选题按分导出为 JSON + 人工「两级标注表」。

**关键缺口**（本提案要补的三件事）：
1. **没有指标定义** —— 现有脚本自述"只做数据导出，不算准确率"。重排是排序/相关性问题，萃取的"命中率"口径**不能直接搬**。
2. **没有金标** —— `golden/` 下只有 `extraction.v2.json`，没有 ranking 金标；标注表靠人肉扫"哪题不对"，主观且易漏。
3. **没有算分脚本** —— 缺少「金标 × 导出 → 指标」的一步。

---

## 1. 核心难点（为什么重排 ≠ 萃取，指标必须重新设计）

1. **不是分类，是"每对相关性 + 排序"。** 萃取一条故事一个正确答案（主观察点），命中率天然成立。重排是对 `(故事 × 候选题)` 每一对做相关性判定，还叠加"档位 + 顺序"。指标要同时回答两问：**档位判对没有**、**排序排对没有**。

2. **错误代价高度不对称，且与"可见性"强相关。** 三类错分伤害天差地别：
   - **高分虚高（false-high）**：把用户其实答不了的题放上首屏（≥85）→ **最伤**，直接砸第一印象。
   - **低分埋没（false-low / buried）**：本可直接答的好题被压到隐藏（<40）→ 浪费好题，但用户看不到，伤害次之。
   - **档位漂移（相邻档，如中判低）**：轻微。
   → 指标必须**按可见性/代价加权**，不能一视同仁地算"总命中率"。首屏的错，权重最高。

3. **与召回纠缠。** `matchByStory` = 萃取 + 三层召回漏斗 + 重排。一道好题"没上榜"可能是**召回没捞到**（漏斗的错），而非重排压低（重排的错）。评估单元必须先划清：**重排只对"进了候选池的题"负责**；"好题从没被召回"归召回评估（matching）管。见第 4 节。

4. **档位阈值是产品参数（85/60/40）。** 金标若用"数字分"标注会被阈值绑死；改阈值就得重标。**解法**：金标标**档位（rubric 语义档）而非数字**，阈值变化只需重算混淆矩阵，金标不动。

---

## 2. 指标体系（提案核心）

**总原则**：金标给每个 `(故事 × 候选题)` 对一个**绝对档位** `∈ {高, 中, 低, 隐藏}`（rubric 语义，见第 3 节）；AI 分数按同阈值映射到同四档；一切指标由「AI 档 × 金标档」推导。人力从"找错"（主观、易漏）转为"给每行标正确档"（客观、完备）——这是最重要的一处口径升级。

### 2A. 主指标（上线闸门 · 按可见性/代价加权）

| 指标 | 定义 | 为什么是它 | 暂定目标 |
|---|---|---|---|
| **首屏精确率 P@首屏** | AI 判为 高(≥85) 的题里，金标也为 高 的占比 | 直接约束"上首屏的题配不配上首屏"，是第一印象的守门指标 | ≥ 90% |
| **虚高率 FalseHigh** | AI 判 高 的题里，金标 ≤低（拿故事答会尴尬/要换故事）的占比 | 头号伤害指标，越低越好；比 P@首屏 更严（只算"离谱的高"） | ≤ 5% |
| **可见区档位命中率** | 可见候选（AI≥40）中，AI 档 == 金标档 的占比 | 用户实际能看到的题，档位判得准不准 | ≥ 85% |
| **埋没率 Burial** | 金标为 高 的题里，被 AI 压到 隐藏(<40) 的占比（仅统计"已被召回"的题） | 好题被雪藏的比例，recall-of-good；对候选池内负责 | ≤ 5% |

> 说明：埋没率的分母只含**已进候选池**的题。"金标该给高、但漏斗根本没召回"的情形单列诊断（见 2C 的"金标未召回项"），不混进重排指标。
>
> ⚠ **埋没率的抽样还原（口径关键）**：埋没发生在**隐藏区（AI<40）**，而隐藏区只标 1/5，直接计数会把埋没**系统性低估约 5 倍**（分子分母同缩水）。故算分脚本对埋没率做**逆概率加权还原**：`埋没率 = N_hidden·p̂ /（可见区金标高 + N_hidden·p̂）`，其中 `N_hidden`=隐藏候选总数（来自导出、全量已知），`p̂`=隐藏样本中埋没占比；还原倍数 `S = N_hidden/隐藏已标数`**用数据实测、不写死 ×5**（稳健于实际标注量偏差）。同时给 **Wilson 95% CI**，报告注明「**CI 宽，仅看趋势；逼近闸门线时对该故事隐藏区全标确认**」。**连带修正**：4×4 混淆矩阵的**隐藏行**同受影响，按同一 S 还原（估计值）。**不受影响**的：首屏精确率 / 虚高率 / 可见区档位命中率——分子分母全落可见区（100% 标注），是精确值。
>
> 更稳妥的两段式（推荐配合"够用即停"）：先用加权估计**筛**；仅当点估计或 CI 上界**触线**，再对涉事故事的隐藏区**全标**（S→1）取定值。便宜筛、贵处才精标。

### 2B. 副指标（质量 · 排序）

| 指标 | 定义 |
|---|---|
| **NDCG@K** | 以金标档为分级相关（高=3/中=2/低=1/隐藏=0），K=首屏容量（暂定 5）。捕捉"档内顺序"，弥补纯分桶看不出的排序质量。 |
| **档位混淆矩阵 4×4** | 「AI 档 × 金标档」全量计数。看漂移方向（系统性偏高还是偏低），对标萃取的分组表。 |
| **序一致性 Kendall τ / Spearman ρ** | 每条故事内 AI 分数 vs 金标档 的秩相关，取宏平均。整体排序吻合度。 |
| **稳定性 Stability** | temp=0 仍有抖动：R=3 重跑，同一对的档位跨轮一致率。对标萃取 98% 稳定性口径。 |

> **NDCG / Kendall τ / Spearman ρ 一律「参考」定位，不得反过来绑架标注设计。** 标注只产出**四档绝对档位**这一件事；排序类指标全部由四档派生（高=3/中=2/低=1/隐藏=0），不要求标注人排序、不要求打连续分。主线永远是 2A 的**四个闸门指标**；副指标看趋势、不作上线门槛。

### 2C. 诊断产出（不进闸门，供反哺 prompt / 反哺金标）

- **虚高 Top 榜 / 埋没 Top 榜**：错得最狠的具体条目明细（故事 + 题 + AI 分 + AI 理由 + 金标档），直接指导改 prompt。
- **分观察点分组表**：哪些观察点重排最不稳（对标萃取分组表）。
- **金标未召回项**：金标标了高/中、但本轮没被召回的题 → 交给召回（matching）评估，不算重排的账。
- **金标缺口项**：本轮召回了、但金标没标的题 → 提示金标不完备，需补标。
- **reason 质量抽检**：随机抽 N 条，人工判理由是否成立（主观，抽检不入闸门）。

## 3. 金标规范（金标怎么建、怎么标）

### 3.1 评估单元与金标文件

- **单元**：`(storyId, questionId) → goldBucket`。
- **复用萃取 100 条故事**（`run-ranking.ts` 已读 `extraction.v2.json`），沿用 `countInAccuracy` 区分域外条。故事层零成本复用，只需为候选题补档位标注。
- **文件**：`scripts/eval/golden/ranking.v1.json`，结构（由 `--blind` 产出的 scaffold 填 `goldBucket` 而来）：
  ```jsonc
  {
    "version": "ranking-v1",
    "bucketRubric": "见第 3.4 节，与 prompt 判定主线同源",
    "hiddenSampleRate": 0.2,          // 隐藏区抽样率，供算分脚本交叉校验（实际还原用数据实测 S）
    "annotator": "张三&李四",          // 双标人
    "annotatedAt": "2026-07-xx",
    "items": [
      { "storyId": "S001", "countInAccuracy": true,
        "labels": [
          // zone 由 scaffold 预置：visible=可见区全标(权重1)；hidden_sampled=隐藏区1/5抽样(算分×S还原)
          { "questionId": "q_xxx", "zone": "visible", "goldBucket": "高", "note": "原样能答，正问对点" },
          { "questionId": "q_yyy", "zone": "hidden_sampled", "goldBucket": "中", "note": "要挪聚光灯" }
        ] }
    ]
  }
  ```
  > **`zone` 为什么必须有**：埋没率与混淆矩阵隐藏行只对隐藏区的 1/5 抽样有标注，算分时要按 `S=隐藏候选总数/隐藏已标数` 加权还原；没有 `zone` 就分不清哪条该还原，还原无从谈起。`zone` 由盲标 scaffold 预置（人不可见，不锚定），标注只填 `goldBucket`。
- **对召回漂移的容错**（关键）：候选集 = 生产实际召回，会随题库/漏斗变动。算分脚本按 `questionId` 对齐：
  - 金标有、本轮召回有 → 正常计入档位命中；
  - 金标有、本轮没召回 → 记入 **金标未召回项**（诊断，不计重排账）；
  - 本轮召回有、金标没标 → 记入 **金标缺口项**（提示补标）。

### 3.2 分批标注 + 够用即停（拍板口径）

不一次标满 100 条。分批推进，**结论明确就停，不为凑数补标**：

- **第一批：40 条故事（分层抽样）**。抽样须覆盖：
  - **6 大维度**均衡（每维度取够代表条数，不偏科）；
  - **必含边界故事**：经**邻居兜底召回**的（`matchedViaNeighbor=true`）、**可见候选=0** 的（首屏/查看更多都无题）、以及 **noMatch** 的——这些最能暴露虚高/埋没。
  - 抽样属**运行期属性**（邻居兜底/可见=0 要跑完才知道），故选批流程为：先全量 `eval:ranking` 导出一次 → 按导出的 `matchedViaNeighbor` / 可见数 / 主观察点维度分层挑 40 个 id → 用 `--only=<40 ids> --blind` 生成盲标表。
- **标完先算指标，再决定要不要第二批**：
  - **首屏精确率 / 虚高率结论已明确**（达标或明显不达标，且样本内方向一致）→ **停，不补标**，直接进 P3 反哺。
  - **数字模糊 / 落在闸门附近 / 样本内自相矛盾** → 再抽第二批补到结论稳定为止。
- 每档粒度：**可见区（AI≥40，含 unscored）全标 + 隐藏区（<40）抽 20%**。隐藏抽样只为估埋没率与混淆矩阵下沿，不必全标。
  - **抽样顺序（决定还原是否成立）**：导出候选按 `relevanceScore` 降序，隐藏区候选亦按分数降序；脚本**每 5 取 1 = 按分数降序的系统抽样**，具**分层**性质——覆盖隐藏区各分数带（30 多分的"接近可见"与深分区都采到），正是加权还原（×S）成立的前提。若改按 id 抽样则退化为近似随机，还原仍成立但失去分层覆盖。**结论：保留"按分数降序每 5 取 1"。**

### 3.3 标注流程（对标萃取"双标 99%"）

1. **双人独立标注 → 对账 → 报一致性**：两人各标，冲突条目对账终裁，报 **Cohen's κ（四档）** 作为"人类天花板"（萃取报了 99% 主观察点一致率，重排目标 κ ≥ 0.8 视为可用）。
2. **盲标**：标注时**隐藏 AI 分数与理由**，只给 `故事 + 题干(中英) + 所属观察点`，避免锚定。→ 需给 `run-ranking.ts` 加一个 `--blind` 变体标注表（现表展示 AI 分/理由，适合快速 QA，不适合建金标）。
3. **同源 rubric**：标注判据 = prompt 的「判定主线 + 4 条硬指引」，金标与模型共用一套定义（公平），但标注人从"故事+题"直接判，不看 AI 结果。
4. **评估反哺金标**：跑出基线后，凡"AI 稳定判对、金标标反"的条目复议修正（萃取修 S018 即此机制），并记入 `重排金标-变更记录.md`。

### 3.4 档位判据（标注手册核心，写入金标顶层 + 变更记录）

直接采用 prompt 已定义的语义，落成标注四档：

| 金标档 | 语义（改不改故事） | 对应分区间 |
|---|---|---|
| **高** | 重心/主语/场景/时间/活动/聚光灯**全不用改**，原样直接充分答，且正答它问的点 | ≥85 首屏 |
| **中** | 沾边，但要换角度/挪聚光灯/换场景/只覆盖一部分/习惯硬套单次 | 60–84 折叠 |
| **低** | 必须换一个不同的经历才能答，当前故事帮不上 | 40–59 折叠 |
| **隐藏** | 完全答非所问，拿这故事答会尴尬 | <40 不展示 |

**边界仲裁细则（标注手册需逐条写，对标萃取 13 条规范）**，至少覆盖：
- **高/中界**：聚光灯要不要挪？要挪即降中（例：故事高潮是"对方道歉"，去答"你说真话的一次"要改重心 → 中）。
- **中/低界**：换角度能答 vs 必须换故事。场景根本没发生（室内独处 vs 户外散步）→ 低。
- **中档三来源**：换场景 / 挪重心 / 习惯套单次，三者都算中，手册各给一例。
- **隐藏门槛**：话题完全无交集才隐藏；沾边但硬凑仍算低（40+），不轻易隐藏。
- **跨语言**：按语义判，不因中英差异误判。
- **cue card（Part 2）vs Part 1/3**：题干取 `cue_card_title` 优先；Part 3 观点题的"能不能答"标准。
- **域外条 / noMatch 故事**：`countInAccuracy=false` 的域外故事、以及 noMatch（零候选）故事的处理——前者出诊断不入闸门，后者单独确认"零候选是否合理"。

## 4. 评估单元决策：端到端 vs 隔离重排

| 方案 | 候选集来源 | 优 | 劣 |
|---|---|---|---|
| **A（推荐·主口径）端到端** | 生产真实召回（现 `run-ranking` 导出） | 完全等于线上；零额外改造；金标只标召回到的题 | 重排指标条件于召回；测不出"好题从没被召回" |
| **B（可选·后续）隔离重排** | 每故事固定候选池，绕过漏斗直喂 `rankQuestions` | 纯测重排能力；可测含召回缺口的埋没 | 需另造固定池；标注量大 |

**已拍板：主口径取 A（端到端）。** B 暂不纳入本期。

> ⚠ **A 的固有风险（须记住并定期处理）**：候选池 = 生产实时召回，**上游（萃取 prompt / 三层召回漏斗 / 题库）任何改动都会改变候选池，导致既有金标覆盖衰减**——原来标过的题这次没被召回（金标未召回项↑），或新召回的题没有金标（金标缺口项↑）。因此金标**不是一次性资产**：每逢上游变更、或算分脚本报出「金标缺口项」比例超阈（建议 >10% 即预警），需**按当次导出补标缺口、复核未召回项**，否则重排指标会因覆盖不足而失真。脚本每轮都会打印这两个数，作为"金标该补了"的信号。

**建议**：**主口径用 A**（产品真相、便宜、复用现有导出），把"召回缺口"通过 **2C 的金标未召回项**移交召回评估；**B 作为后续可选专项**，只有当怀疑"重排本身"能力时再单独隔离测。这样重排评估与召回评估各司其职、不互相背锅。

## 5. 上线标准（暂定闸门，待基线 + 天花板校准）

对标萃取"严格 94.9%、接近人类双标天花板 99%"的定档方式，重排暂拟：

**闸门（4 条主线，决定上不上线）**：

| 闸门 | 暂定线 |
|---|---|
| 首屏精确率 P@首屏 | ≥ 90% |
| 虚高率（金标≤低） | ≤ 5% |
| 可见区档位命中率 | ≥ 85% |
| 埋没率（金标高被压隐藏） | ≤ 5% |

**参考（看趋势，不作门槛）**：NDCG@5、稳定性、Kendall τ、混淆矩阵。

> 这些线是**占位**，须在跑出首个基线、并测出人类双标 κ 上限后回填——不作线上承诺值（同萃取"理想输入上限≠线上值"的保留）。

## 6. 落地路线（对标萃取的机制沉淀）

- **P0 建金标（第一批 40 条）**：全量 `eval:ranking` 导出一次 → 按 `matchedViaNeighbor`/可见数/维度分层挑 40 个 id → `eval:ranking -- --only=<40 ids> --blind` 生成盲标表 → 双人盲标（可见区全标 + 隐藏区抽 20%）→ 落 `golden/ranking.v1.json` + `重排金标-变更记录.md`（含标注手册）。
- **P1 算分脚本**：`scripts/eval/run-ranking-score.ts`（或给现 `run-ranking` 加 `--score` 分支），读金标 + 导出 → 输出第 2 节全部指标 + 诊断 md。加 `npm run eval:ranking:score`。给现导出表加 `--blind` 盲标变体。
- **P2 基线**：R=3 全量，产出首个重排基线报告进 `results/`、进 git，校准第 5 节闸门与 κ 天花板。
- **P3 反哺**：按虚高/埋没 Top 榜改 prompt（重点压虚高），复议"AI 稳对、金标标反"的条目。
- **P4 收尾**：`重排环节-评估阶段收尾档案.md` + 沉淀机制：**"改 prompt / 换模型 → 先跑 `npm run eval:ranking:score -- --runs=3` → 对比基线 → 报告进 git → 再合并"**。
