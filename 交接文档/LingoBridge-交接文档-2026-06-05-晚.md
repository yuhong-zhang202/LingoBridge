## 二、这一轮的完整改动清单（按执行顺序）

### 改动 1 · 修复第二层借道只查主标签的 bug（matching.ts）

**问题**：三层漏斗的第二层（primary 查不到题时，改用 secondary 借道查题）调用 `getQuestionsByObservation` 时传了 `includeSecondary=false`，导致**只能查到以 secondary 为主标签挂载的题，查不到以 secondary 为副标签挂载的题**。

**为什么是定时炸弹**：当时第四个验收故事（小组抢功）"碰巧"配上了，纯属运气——它借的 REL_11 恰好是某道题的主标签。但设计里关键的借道路径（如 VAL_03 坚持原则借道 GRO_07，而 GRO_07 在"An Important Decision"卡上是**副标签**）会因此彻底跑不通。

**修复**：只把第二层 secondary 借道这一处的 `includeSecondary` 改为 `true`。

**严格保持不变（产品决策，勿改）**：
- 第一层查 primary 主维度题：保持 `includeSecondary=false`（主维度只认主标签）。
- 第一层追加查 secondary 主标签题（副维度命中支）：保持原样。
- `getQuestionCountByObservations`（素材库匹配计数）：保持默认 false（匹配数只算主标签）。

**验证铁律印证**：此 bug 是"tsc 过 ≠ 运行时对"的典型——类型完全合法，逻辑悄悄错。靠临时插桩日志（见改动 4 的方法）才定位到 `includeSecondary: false`。

### 改动 2 · 坚持原则维度落地"温柔收尾页角度引导"（NoMatchView.tsx）

**背景（基于题库实证，重要）**：
- 经查 `ielts_questions_enriched.json`，**VALUE 整个维度在题库原始文件里作为主标签出现次数为零**。诚实（VAL_02）、公平（VAL_01）、坚持原则（VAL_03）三个点，都是后期在 Supabase 手动挂载或定性为灵魂标记。
- "坚持原则"严格对应的 Part3 题，题库里**没有**。最接近的是"A Time You Told a Truth（说实话）"卡下的一道 "Do you think it's more important to win a game or follow the rules in sports?"（守规则 vs 赢）。**全题库唯一沾"坚守原则/守规则"边的内容，都聚在"说实话"卡底下。**
- 实测："拒签合同"类纯坚持原则故事，萃取多次跑 secondary 全部为 null（模型坚定判断它只有"坚持原则"一个角度，没有独立第二叙事线）。结论：**纯坚持原则故事天生缺少可借道的 secondary，走温柔收尾是正确行为，不是 bug。**

**产品决策**：不为坚持原则硬凑题（撤销"借道重要决定卡"那条勉强路径的依赖），改为在温柔收尾页**引导用户切换到"说实话/表达立场"角度补充语料**——因为坚持原则的故事内核里，往往真实包含一段"表达立场、说真话"的经历，只取决于用户有没有讲出来。用户补讲后，新语料自然带出诚实（VAL_02）信号，正常配到"说实话"卡。**这是基于用户真实表达的引导，不是后台凭空安角度。**

**触发条件**：`primaryDimension === '价值底色'` 且走到第三层（温柔收尾）。
- 一条规则自动覆盖**坚持原则 + 公平**两个点。
- **自动排除诚实**——诚实直配"说实话"卡（走第一层），不会到温柔收尾，所以不会触发引导。

**页面最终形态（NoMatchView，版本 B 舒展布局）**：
- **删除**了原长共情文案（"别停下来，表达是有意义的…"整段）。
- 保留：嫩芽图标（放大）+ "题库还没有这道题" + "我们识别到你的故事属于" + 维度行。
- 留白舒展，吸收删文案后的空间，符合温柔收尾"温暖低压、不催促"调性。
- **角度引导卡**（仅 value 维度显示）：
  - 顶部绿色维度标签 `{primaryDimension} · {primaryPointName}`（动态，跟随真实维度；公平故事显示"公平感与正义"，不写死维度名）。
  - 标题：`这类故事的背后，常常藏着一次「说实话、表明态度」的时刻`（「说实话、表明态度」用 brand-primary-dark #B5663A 点缀）。
  - 副文案：`如果你愿意，可以尝试从这个角度讲述，也许会遇到更贴合的题目。`
  - 主按钮：`切换角度讲述 →`（白底渐变描边，rounded-full，**非渐变填充**）。
- **三个出口的最终跳转目标**（注意都各自不同，勿串）：
  - `切换角度讲述` → `router.push('/')`（首页，让用户整理思绪）
  - `重新讲一个故事` → `router.push('/')`（首页 —— 本轮用户明确改为首页，原为录音页）
  - `换一道雅思题来练 →` → 原题库目标不变
- 文案统一用"这类故事"而非写死"坚持原则"，避免公平故事显示"坚持原则"的穿帮。

**关键设计认知（勿推翻）**：
- 公平（VAL_01）**不能删**——交接文档原决策点 1 已定性它是"灵魂标记，没题可配不是缺陷"。它有两条蹭题可能（借道道歉卡 REL_11 / 往说实话守规则题靠），但主要价值在让公平故事被正确归类、走对温柔收尾。
- 三个价值点都不删：诚实有家（说实话卡）、坚持原则有邻居（可引导往说实话靠）、公平是灵魂标记。

### 改动 3 · 修复首页文字输入断链 bug（src/app/page.tsx）

**问题**：首页文字输入框输入语料、点"开始匹配 →"后，`router.push('/article')` 跳到了**废弃的旧版生成文章页**，且用户输入的 textStory **被完全丢弃没传出去**。`/article` 用 mock 数据（"我今天去了一个公园"），与主流程无关，是过时老链路残留。

**修复**：改为复用录音页完全相同的入口——
`router.push(\`/restructure?rawText=\${encodeURIComponent(用户输入)}\`)`，让文字输入与语音输入合流走正确链路（整理 → 匹配）。加了空输入兜底（空则不跳）。

**关键点**：参数名**必须是 `rawText`**（/restructure 页读的就是 rawText，对齐录音页第 57 行写法），编码用 `encodeURIComponent`。

**安全性**：全项目只有 page.tsx 这一处引用 `/article`，修复后 `/article` 成为无入口的死页（待后续清理，本轮未删）。`/article-view`（视觉基准页）是另一独立路由，不受影响。

### 改动 4 · 修复萃取对"真实冲突角度"识别不稳定（extraction.ts）

**问题**：同一个含真实冲突事件的故事（小组抢功：抢功 → 私下摊牌 → 对方道歉），萃取多次跑 secondary 时有 REL_11（冲突角度）、时为 null，不稳定。

**根因**：上一轮为治"副标签乱打"（把故事里随便提到的配角误标人际）收紧了 SYSTEM_PROMPT 规则 2 的"特别注意"段落。结果结构失衡——禁止性反例（配角≠第二角度）三行、语气强，而"真实冲突事件=合法第二角度"的正向说明只有半行、藏在 REL_11 vs REL_03 对比句里。模型读完一大段"配角不算"后，把"摊牌"里的对方也误判成配角，压制了 REL_11。

**修复（只改提示词，不动逻辑，不放松现有反例）**：
1. 在"特别注意"段落补一条与反例结构对称的**正向区分原则**：真实发生的独立冲突/摊牌/对抗事件（"那场冲突本身有叙事重量"，非"有个人在场"）可作合法第二角度，判断标准是「去掉冲突那段，故事是否损失一个独立的叙事层？」。
2. 补一条 few-shot 示例（小组抢功）。**示例 primary = VAL_01（公平感），不是 VAL_03** —— 该故事核心是"被不公平对待、为自己争取公正"，实测 primary 一直稳定 VAL_01。（侦察报告初稿误写成 VAL_03，已修正；若不修会反向污染 primary 判断。）

**保持不变**：现有"配角≠第二角度"反例（旅行提朋友、爸爸帮决定）原样保留，不弱化。REL_11 观察点定义未动（其定义本无问题）。

### 改动 5 · 清除所有临时 DEBUG 日志（extraction.ts / matching.ts）

定位问题期间，在萃取返回处和三层漏斗每层加过 `[DEBUG extraction]` / `[DEBUG funnel]` 临时 console.log。全部问题验证完成后已删干净（全局搜 `[DEBUG` 为 0 命中），未触碰任何业务逻辑。

## 三、关键设计决策（为什么这么做，避免后人推翻）

1. **第二层借道必须 `includeSecondary=true`，第一层和计数必须 false**：三处职责不同。第二层要能查到副标签挂的题（借道核心），第一层只认主标签（主维度匹配的产品定义），计数只算主标签（素材库数字的产品定义）。三者勿一刀切。

2. **纯坚持原则故事走温柔收尾是正确的，不是 bug**：题库实证 + 萃取多次实测都支持。坚持原则没有自己的主标签题，硬借"重要决定"卡会答非所问（那张卡的 Part3 全讲"如何做决策"，与"坚守底线"内核不符）。

3. **角度引导是"前台引导用户补讲"，不是"后台凭空安角度"**：后者（让萃取自动给坚持原则补打诚实副标签）会与改动 4 的"精准识别"方向打架、且违背"基于用户真实表达"的产品内核。前台引导让用户自己讲出说实话的内容，新语料自然带出诚实信号，干净。

4. **引导触发用 `primaryDimension === '价值底色'` 一条规则**：因为 value 维度下能走到温柔收尾的，实际只有坚持原则和公平（诚实直配不会到这步）。无需精细到具体 pointCode，简单且不易错。

5. **萃取修复是"补正例、平衡结构"，不是"放松闸门"**：松错方向会让咖啡故事（提到妈妈）又被误标人际。改动 4 已回归验证咖啡故事 secondary 未误标。

6. **首页文字输入与语音输入应合流到同一入口**（`/restructure?rawText=`），不另起链路。`/article` 是死页，勿复活。

## 六、后续路线图 + Backlog（更新版）

### 第一阶段（核心质量）剩余

- **相关性排序（P1，第一阶段收口）**：用 LLM 或 embedding 给每道题打相关性分。这是让匹配真正精准的根治方案——观察点粗粒度是设计权衡（粗=覆盖广、细=精准但维护重），相关性排序在不牺牲覆盖的前提下提升精准度。做完后把"临时前8折叠"升级成"按相关性阈值展示"。

  **本轮攒下的两个现成目标测试用例**（做相关性排序时拿来验）：
  1. **咖啡故事 → 打字题**：手冲咖啡故事 primary=成长演进·技能，但"技能"观察点下挂的是 typing（打字）题，于是配出一堆"你喜欢打字还是手写"等完全不相关的题。期望相关性排序后：打字题被压到很后或滤掉，咖啡/爱好/放松类题排上来。**这是观察点粗粒度问题的典型代表，不是 bug，本轮有意不修，留给相关性排序。**
  2. **小组抢功 → 最相关题被折叠**：最相关的题因为是 secondary 借道命中、被排在主维度题之后并压进折叠，最不相关的反而排最前。暴露"主维度题永远在前"排序规则的软肋。期望相关性排序后按相关度而非主/副位置排序。

- **教练话术用上灵魂标记（P1）**：并入 practice 重写任务，让 VAL primary 引导教练方向。数据层 primary 已透传到位。

## 七、验证铁律（延续，本轮再次印证）

每个写库/RPC/逻辑改动都要在 app 实测真实数据，再往下走。**代码 tsc 过 ≠ 运行时正确**——本轮第二层借道 bug（`includeSecondary: false`）就是 tsc 完全合法、逻辑悄悄错的典型，靠临时插桩日志（在萃取返回处和漏斗每层 console.log 出 primary/secondary/命中层级）才定位到。

**临时插桩日志是定位运行时逻辑 bug 的有效手段**：当 ApiLogger 只记录 service/cost、看不到业务中间值时，临时加 `[DEBUG ...]` log 打印关键变量、跑完即删，比 squint 看结果可靠得多。注意：萃取/匹配是服务端跑的，日志在 `npm run dev` 终端，不在浏览器 DevTools。
