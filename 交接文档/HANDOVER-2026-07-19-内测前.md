### 方案要点（完整方案由上一会话的排查产出，要点如下）

**成本认知（读码算出的真实单价）**：
- 一条完整主链路（60秒录音→整理→匹配→分析→练习3轮）≈ **¥0.20**，其中 **90% 是 ASR**
- 文本类 LLM 接口误打几百次也就几块钱
- **真正的钱坑**：`MAX_AUDIO_BYTES = 10MB`，大音频单次可达 ¥3–5 → **测试音频必须 ≤15 秒 / ≤300KB，脚本内硬检查**
- **全套 AI 预算：¥20 封顶**

**分层**：
| 层 | 测什么 | 成本 | 关键点 |
|---|---|---|---|
| **L0 冒烟** | 部署可用性、鉴权闸未被绕开（`/api/version` 版本号对不对） | ¥0 | 5 分钟 |
| **L1 端到端** | 主链路 + 白名单准入 + 同意闸 + 越权 + 配额 + 删号；**验证 matching 存档命中不重复计费** | ≈¥2 | 部分需产品方手工（真机录音/PWA/SW更新） |
| **L2 并发** | 压**不花钱**的接口，分三面：a) `/api/version`（纯 Node）b) `/api/questions?mode=switch`（Supabase 数据面）c) 带 token 接口（**Supabase Auth 面，每请求 1 次 `getUser`，最易撞额度**） | **¥0** | 目标不是压崩，是**证明对 3 req/s 的内测需求有 10 倍余量** |
| **L3 转写并发** ⭐ | 同时 1→3→5→8 个 `/api/transcribe`，找 ffmpeg 真实拐点 | ≈¥1.3 | **信息量最高的一层**；用注册账号（200/天） |

**判读陷阱（务必注意）**：
- `/api/transcribe` 的 `export const maxDuration = 60` 是 **Vercel 语义，在 Zeabur 上不生效**。L3 并发 8 若出现 502，**先怀疑 Zeabur 网关超时，不是应用挂了**——用「进程有没有重启 + 内存曲线」区分。
- 脚本拿 JWT：登录是客户端直连 GoTrue，需 `POST ${SUPABASE_URL}/auth/v1/token?grant_type=password` + `apikey: ANON_KEY`。**token 1 小时过期**，长跑脚本要支持 refresh。
- 测试账号**必须先加进 `beta_allowlist`**（白名单已生效）。

**监控三处**：Zeabur 面板（CPU/内存/流量）、`/dashboard` 成本看板（每档结束看花费增量 = 成本刹车）、Supabase 面板（Auth 请求/连接/带宽额度）。

**清理**：用专用测试邮箱 → 测后 `/api/account/delete` 删号 → 从 `beta_allowlist` 移除 → 匿名会话数据按时间窗口 SQL 清。**⚠️ `api_usage_logs` 删号时只去标识化、行保留**，测试费用会永久留在成本看板 → **记录测试时间窗口供对账**（产品方已选此方案）。
