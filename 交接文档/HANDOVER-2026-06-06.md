## 0. 一句话项目定位
LingoBridge 是面向雅思口语备考生的练习 App。核心理念：把用户真实的生活故事，转化为可用于即兴表达的口语素材，通过"匹配真题→个性化分析→对话练习→反馈"形成闭环。不是死记题库，而是练"用自己的经历自然作答"。

## 1. 技术栈与基础设施
- 框架：Next.js 14.2.35（App Router）+ PWA；UI：Tailwind CSS；部署：Vercel
- 数据库：Supabase（Postgres + RLS 行级安全 + 匿名 auth）
- AI：全部走阿里云千问（DashScope，OpenAI 兼容接口）。语音转写用豆包 ASR。
- 仓库根目录：~/Desktop/LingoBridge
- 启动：`npm run dev:log`（实时日志 + 同时写入项目根 dev.log，重启终端不丢历史）；原 `npm run dev` 保留。
- 查日志：`grep ApiLogger dev.log`（看每次 AI 调用的 service/endpoint/成本）、`grep "api/matching" dev.log` 等。

## 2. 主流程（用户视角 6 步）
语料输入(/recording) → AI整理确认(/restructure) → 题目匹配(/matching) → 侧重点分析(/analysis) → 练习对话(/practice) → 卡片反馈(/feedback)
StepBar 5步标签：故事 / 整理 / 题目 / 分析 / 练习

## 3. 核心架构：题目匹配的三段式（最重要，必须理解）
用户讲一个故事，系统从几百道雅思题里挑出"他能用这个故事答好"的题。分三步：

**第一步 萃取（src/services/extraction.ts）**：qwen-plus 读故事，从 48 个"观察点"里选出 1 个主维度(primary) + 最多 1 个副维度(secondary)，各带一个 pointCode（如 EMO_04）和一句 reason。观察点是横跨 6 个维度的分类标签：情绪内核(emotion)/人际羁绊(relationship)/空间感知(space)/精神栖所(spirit)/成长演进(growth)/价值底色(value)。萃取的判断逻辑很娇贵（"配角≠第二角度""被冤枉归冲突不归诚实"等边界），48 点的完整 taxonomy + few-shot 全部写死在 extraction.ts 的 SYSTEM_PROMPT 里。

**第二步 召回（三层漏斗，src/services/matching.ts 调 src/lib/db/questions.ts 的 getQuestionsByObservation）**：用萃取得到的 pointCode，去 question_observation_links 关联表（字段 observation_point_id / question_id / is_primary）查"挂着这个观察点的题"。
- 第1层：用 primary code 查 is_primary=true 的题；若有，再补 secondary code 的题（也 is_primary=true），用 Set 去重。
- 第2层：primary 查不到题、但有 secondary → 用 secondary code 查 is_primary 不限（含主+副标签），标记 matchedViaSecondary。
- 第3层：primary 空且无 secondary → noMatch，返回空（前端走"题库还没这道题"的温柔收尾页）。

**第三步 相关性重排（src/services/ranking.ts）**：把召回的候选题 [{id, en, zh, obs}]（en/zh 优先用 cue_card_title，回退 question_text）交给 qwen-plus，逐题打 0-100 分。判分核心标准是"要不要改动故事本身才能答"：不用改=高(≥85)，同故事换角度=中(60-84)，得换一个故事=低(30-59)，<30 离题。temperature=0.2（降低波动、让结果可复现）。返回 {scores:[{id,score,reason}]} 按分降序。失败则回退到漏斗顺序。

**观察点是这套系统的护城河**：它是连接"用户故事"和"题库"的共同分类坐标。题库每道题事先归到某些观察点，故事被萃取到某个观察点，两边用同一套坐标才能对上号。竞品能抄"让 AI 排序"这个动作，抄不走这套 taxonomy 的设计。
**为什么不用"把全部题塞给一个 AI 调用"**：那是 demo 形态；题库几百道、用户多起来后，全塞进去又慢又贵又不稳。两段式（便宜召回 + 精排）是规模化的必需。
**为什么不加"维度匹配加分公式"**：曾讨论并否决——那会退回粗粒度规则匹配（正是早期已修复的 bug），且与 LLM 打分两个信号打架、难调。要提准确率，改 prompt（观察点边界 / 判分标准），不要加公式。

## 4. 前端匹配页分档展示（src/app/matching/page.tsx）
阈值常量在 src/lib/constants.ts：SCORE_HIGH=85 / SCORE_MID=60 / SCORE_LOW=40。
- 高匹配(≥85)：默认显示。
- 中匹配(60-84) + 低匹配(40-59)：折叠，由单个"查看更多 N 道 →"/"收起 ↑"按钮切换。
- <40：隐藏（软折叠，非硬删）。
- 高匹配卡片不显示"需切换角度"橙标（那标签只在中/低匹配出现）。

## 5. 端到端链路（页面 → API → service → DB）
recording → POST /api/transcribe(豆包ASR) → POST /api/restructure(qwen-flash, 清洗成故事) → 写 corpus 表(客户端 Supabase) → /library
library 选故事 → /matching?story=...&corpusId=...
matching → POST /api/matching → matchByStory()[萃取+三层漏斗召回+重排] → 客户端 saveExtraction 写回 corpus 行 → 点"练习" → /analysis?questionId=...&storyId=...&story=...
analysis → GET /api/analysis → getCorpusByIdServer()(service_role 绕 RLS 读故事，URL 的 story 作兜底) → generateAnalysis()(qwen-plus，有故事时个性化) → 点"开始练习" → /practice?questionId=...
practice → POST /api/practice → buildScaffold()(getQuestionById + getQuestionsByParent + generateAnalysis) + coachReply()(qwen-plus 英语对话教练，30s 超时)；POST /api/practice/polish → polishSentence()(qwen-plus 润色 + 中文提示)
所有 API route 都 fire-and-forget 调 logApiUsage() 写 api_usage_logs 表，供 /dashboard 消费。

## 6. 当前模型与成本（全部已迁千问）
- MODEL_EXTRACTION / MODEL_RANKING / MODEL_ANALYSIS / MODEL_PRACTICE = 'qwen-plus'（在 constants.ts）
- restructure 用 qwen-flash；转写用豆包 ASR
- ranking temperature = 0.2
- 每次各步成本量级（dev.log 实测）：restructure ~¥0.00015；matching(萃取+排序) ~¥0.0012；analysis ~¥0.00145；practice ~¥0.0006
- 迁移前 matching 用 Claude Sonnet 约 ¥0.038/次 → 迁千问后约 1/30

## 9. 已知问题 / 需处理（重要）

- **URL 携带故事原文**：matching→analysis 跳转时 story 文本明文随 URL 传递（刷新/分享会暴露故事原文）。当前 analysis 已改 service_role 从 DB 读、URL 仅作兜底；可后续做小清理彻底去掉 URL 的 story。内测阶段可接受。
- **题库英文零星拼写错**：曾发现题库个别英文题有拼写错（如 "next ve years" 应为 "five"）。本轮只修中文未动英文，可后续单独清。

## 11. 开发规则（每次任务必守）
- 接 UI 任务先读：ENGINEERING.md → design.md → src/app/article-view/page.tsx。
- 一次只改指定文件，其它一律不动；一次只动一个变量，便于定位。
- 文件长度：Page ≤150 行 / UI 组件 ≤80 行，超出拆到 src/components/。
- 颜色：禁内联色值，统一 Tailwind token；与现有 token 冲突时采用项目原有 token。
- 渐变：仅用于边框描边（外层渐变 + padding:1px），禁 border-image，禁渐变填充背景。
- 数据放 src/data/，类型放 src/lib/types.ts，页面间传值用 URL params。
- DB 写由人手动在 Supabase 执行，Claude Code 只生成脚本/SQL，不直接写生产库。
- tsc 过 ≠ 运行时对：AI 相关改动必须在 app 里跑真实故事验证，并查 dev.log 确认 service/成本，不能只信 tsc。
- 验证习惯：改 prompt/数据流后，宁可先加临时调试日志（[XxxDebug]）确认数据真到位，再下结论；确认完删掉调试日志。
