## 三、FINDINGS（真实项 + 处置）

1. **🔴→✅ 项目级控制台配置缺口（真实事故，本次核心教训）**
   迁完切 Zeabur 后线上点「同意并开始」报「保存同意记录失败」，根因是**新项目默认没开「匿名登录」**（应用靠匿名建 user，无 user 写不了同意记录）。`db:push` 只迁 DB schema/数据/RLS，**Auth / URL / SMTP 等项目级设置全在控制台、迁不过来**。
   - 处置：产品方已开匿名登录；完整清单已写进 `交接文档/Supabase迁移-法兰克福到新加坡.md` 步骤 5.5。
   - 关键项：匿名登录**开**、Email provider + 允许注册**开**、**Confirm email 关**（无 SMTP、国内收不到邮件，不关则注册全卡）、Site URL = `https://lingobridge.zeabur.app`、Redirect URLs = `https://lingobridge.zeabur.app/**`（单条通配即可）、SMTP 不配（密码重置走 `gen-reset-link.mjs` 手动生成）。

2. **🟡 eval:ranking 金标失效**
   `ranking.v1.json` 按题目 **UUID** 绑定（消费方 `run-ranking-score.ts`），全量导题重生成 UUID → 金标旧 UUID 全失配。**但这并入已排期的「金标补标」即可**（本就因换季失效，见 [[season-import-stales-ranking-gold]]），补标对着新加坡库做即天然绑新 UUID，**无需额外紧急重映射**。`extraction` 金标按 S-id、不受影响。
   - 隐蔽点：eval:ranking 红灯会被当「已知换季失配」忽略，从而**掩盖真回归**——补标前不作有效信号。

3. **🟡 旧法兰克福库仍在线可写（脑裂/清理）**
   Zeabur 已切新加坡、内测前，风险低。建议回滚窗（3–7 天）后 **Pause 旧项目**，彻底消除双写可能。

4. **🟢 `--seed-all` 无运行时护栏 → 已修**
   加了「本季已有行则拒绝 `--apply`」守卫（dry-run 不拦），已实测拦截。

5. **🟢 3 文档旧 ref → 已清理**（2026-07-22）。

6. **🟢 服务端匿名账号泄漏 → 部分修**
   `getRandomSwitchQuestion` 的 `ensureSession()` 在服务端冷启动会 `signInAnonymously` 建垃圾匿名账号（旧库 797 匿名 auth 行的来源之一）。该函数已去掉 ensureSession（两表 RLS 关、公开可读）。**同模块另 5 个读函数同模式，留后续单独评审。**
