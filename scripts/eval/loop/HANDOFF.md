```
S072 · SPI_05 一件对你特别的物品
故事：我一直戴着外婆留下的那块旧手表，走时已经不准了，
      但表带上有她用圆珠笔点的一个小蓝点，我舍不得修。

题：一件你离不开的东西 — Describe something that you can't live without
```

**AI 三轮理由高度一致，在争同一件事：「离不开」是情感的还是功能的？**
> 轮1「故事强调**不舍与纪念**，未说明该物在**日常功能上不可替代**」
> 轮2「'离不开'需强调**功能性不可替代**」
> 轮3「强调**纪念意义而非功能依赖**，'离不开'缺乏**生活刚需**支撑」

**同故事另两条金标高（"旧物品"/"重要旧物"）AI 给了 95/94** —— 那两道问的正是纪念意义。
**唯独这道问"离不开"的，AI 认为语义不同。而这条金标的 note 是空的。**

**这是「AI 稳定分歧 + 理由引用 rubric 判据（重心要挪）」的教科书形态**，够格进金标复审队列。
**但方向与今天那 8 条相反**：今天全是金标偏松，**这条如果 AI 对，是金标偏严**。

### seed 调查结论：**它不是「落后于重译」，是第三个版本**

```
seed.zh == 重译前的 DB :  22 / 224
seed.zh == 重译后的 DB :  24 / 224
两者都不等（第三种值） : 198 / 224   ← 关键
```
铁证：
```
036065b6  EN     : What technology do you use at work?
          seed   : 你工作中用什么技术？
          重译前DB: 你在工作中用什么技术？   ← 重译前 DB 就已和 seed 不同
          重译后DB: 你在工作中用什么技术？   ← 重译根本没动它
```

**这条题重译前后完全一样，但 seed 就是不同 → seed 与 DB 早在 2026-06-06 重译之前就已脱钩。**

### 3.0 三档直出：提出 → 实施 → 红队判 ❌ → 回退

**产品决策（不变，仍成立）**：高首屏 / 中折叠 / **低不展示**。依据实测——低档在模型输出里是**假精度**：40-59 区间的 21 条候选**全堆在 40 一个点上**，题目显示与否取决于模型凑整到 40 还是 35（台账 042）。

**实现方式换过一次**：
1. 先试**模型直出 tier**（`{id,q,reason,tier}` + `TIER_SCORE={high:90,mid:70,low:30}` 映射回分数）
2. 我报告「stability 81.8% → 89.2%（+7.4pp）」
3. **红队判 ❌ 刷分**，我独立复算后接受
4. **回退到 reason-first 0-100，三档改由代码两条线映射**（`≥85` 高 / `[60,85)` 中 / `<60` 不展示）

**为什么 +7.4pp 是假的**（这是本文档最该记住的一条）：
```
算 stability 的 aiTierOf 是四档：≥85高 / 60-84中 / 40-59低 / <40隐藏
而 TIER_SCORE.low = 30 < SCORE_LOW = 40 → 「低」桶物理不可达，low 全落「隐藏」桶
实测坐实：三档配置下全部候选 score 只有 {30, 70, 90} 三个哨兵值
→ 所谓四档，在该配置下只是三档
→ 81.8% vs 89.2% 是拿旧配置的四档分母比新配置的三档分母，尺子在中途被换掉了
```
**同尺子重算**（统一 `≥85→high / 60-84→mid / <60→low`，分母三组同为 148/148）：
```
① score先(0-100)   89.9% (133/148)   四档口径 81.8%   并档白送 +8.1pp
② reason先(0-100)  91.9% (136/148)   四档口径 81.8%   并档白送 +10.1pp
③ 三档直出          89.2% (132/148)   四档口径 89.2%   并档白送  +0.0pp
```
**并档效应本身值 +8.1~+10.1pp，超过声称的 +7.4pp 全部涨幅。③ 是三者中最差的。**

### 3.2 036 修复：埋没率 HT 冻结权重（`881d4dd`）

**旧实现两处错**：`scale = hiddenTotal / n` 每轮实测重算 →（1）权重应是历史入选概率的倒数（常数），实测已漂 3.457→3.661→**4.441**；（2）可见线挪到 60 后 `hiddenTotal` 吞进 40-59 段，而那段在金标里是 `zone=visible` 的**全量标注区（π=1）**，却被全局倍数一并放大。

**新实现**：`scripts/eval/hidden-sample-weight.ts` 的 40 个故事 `{n, k}` 冻结表 + `sampleWeight()`，**运行时零计算**。

**报告里的自证行**：
> ⚠️ 本轮导出隐藏区 **262** 条 vs 冻结框 **204** 条（可见线已挪，权重不随之变——这正是本次修复的目的）

**混淆矩阵一并改了**——它此前也在用同一个 `scale`，正是「高行·低=6.66 而虚高榜只数 4」的成因。

**三个设计决定**：
1. **逐故事而非全局常数 204/59**：π_i 在 1.0~0.2 之间变，**40 个故事里 23 个 n_i≤5**——那唯一被抽中的是**确定性观测**（π=1），全局常数会把它当 3.46 条用
2. **表存 `{n,k}` 而非只存商**：`w=4` 可能来自 `n=4,k=1` 也可能 `n=16,k=4`，**反推不唯一**（10 个权重值有歧义；第一版测试正是栽在这）
3. **CI 刻意降级不硬造公式**：点估计 HT 加权；区间用未加权 Wilson 映射并**显式注明口径不同**

### 3.3 抽样框悬案：一个 `ceil` 困惑了一整天

```
声明 hiddenSampleRate: 0.2 → 204 条应抽 ≈41 条
实际金标里 hidden_sampled = 59 条        ← 多 18 条
```
**真相**：`run-ranking.ts:490` 的抽样是 **per-story** 的 `hidden.filter((_, i) => i % 5 === 0)`——每个故事各自从 0 开始数 → **必取第 0 条** → 实际抽 `ceil(n_i/5)`。40 个故事各自向上取整，累积 **204 → 59**。
已验证：**逐故事 id 集合 40/40 与金标 zone 完全一致**。
→ **真实平均入选概率 = 59/204 = 28.9%，不是 20%。**

**抽样框基于管道错位修复【前】的导出**（`00-20`）。产品方定性：**估计无偏、方差受损**——错位交换的是同一故事内两道题的 `{score,reason}`，故事内分数集合不变 → 每故事 `ceil(n_i/5)` 的**数量**与分层性质不受影响（无偏）；但**哪一条**被抽中受影响（方差受损）。
→ **埋没率闸门降级为烟雾报警：只报非零，不报量级。** 恢复精度的路径是金标 v2 重建抽样框。

### 结论二：`temperature: 0` 不代表确定性

### 结论三（重要）：稳的和不稳的，分界线正好是「分母由谁控制」

**稳的那几条，分母都由金标定死**（故事总数 40 / 金标标注对 148 / 金标高总数 11）。

## 7. 红线设计四原则（已写进 LOOP.md，这里给实证）

**1. 精确率天然可用"少预测"刷分，必须配召回率。**
实测：一次改动让首屏精确率 40.9% → 52.9%，看着涨 12 点。逐条核对是 **9/22 → 9/17**——**命中的就是同样那 9 条，连集合都一模一样**，掉出分母的 6 条没有一条是金标高。把分母摁回 22 = 40.9%，**零改善**。
对策：召回率分母 = 金标高总数（11），**由金标定死，AI 控制不了**。踢候选出高档 → 精确率涨、召回率不动 → 一眼看穿。

**2. 分母必须用金标定死的量，不能用 AI 能控制的量。**
实测：首屏可用率分母误用 `len(d['stories'])`（导出全部故事）。`run-ranking.ts` 一改，导出从 40 变 100，而金标只覆盖 40 → **12.5% 被算成 5.0%，报了个假 FAIL**。
按金标对齐的口径天然抗漂移（召回精度按 gold∩recalled 算，分母漂移时纹丝不动），按产物规模算的不抗。

**3. 一条红线只防一个方向，成对的红线才防得住取舍。**
只守"精确率↑ + 虚高率↓"，最省事的刷分法是把所有候选压到阈值以下：两条都变好，用户看到空屏。所以要有"首屏可用率不许跌"对冲。**实测拦住过一次真实的收紧刷分。**
> 设计新红线时先问：想刷这条线最省事的做法是什么？那个做法会伤到什么？把那个"什么"也变成红线。

---

**4. 参数与现实对不上时，解释差额，禁止用"自适应 / 稳健于偏差"绕过。**
> **声明让位给实测的每一处，都是一个潜伏 bug。**

实证：抽样声明 `0.2`、实际 59 条（理论 41），**差 18 条**。这个差**当天就被发现了，还被写进注释**：
> 「用数据实测 S…**不写死 ×5，稳健于实际标注量偏差**。」
> 「`hiddenSampleRate // …算分优先用数据实测 S，此值仅交叉校验/留档`」

作者知道偏离，选择"稳健于偏差"绕过去——**那个绕法就是 036 这个 bug 本身**。不是疏忽，是一次深思熟虑的妥协：把没查清的偏差用"自适应"包装成特性。
> **失手不在没发现差额，在发现了却选择适应它，而不是解释它。**

同形状至少四处：`hiddenSampleRate: 0.2`、`ExtractionPick.reason` 类型谎言、`topic_only` 靠数据约定、`?? 100` 当容错。**全是：写下一个声明，然后让代码去适应它不成立的事实。**

**原则 4 的实操细则**：**挪任何阈值前先看分数直方图，线放凑整谷底。**（原则防态度，细则防手法。）
模型的凑整点是 10/5/25/15/20/**40**/35 —— 旧线 40 踩在密集峰（5.02%），新线 60 落谷底（1.10%），**低 4.6 倍**。

## 10. 踩过的坑（新窗口最容易重犯）

**① 聚合数字会骗人 —— 总分回到基线 ≠ 修好了**
案例：S036 首修后萃取总分从 93.6% "恢复"到 94.9%，真相是 **S041 恰好恢复(-1错) + S100 新冒一个错(+1错) + S036 本身原地不动** 的巧合。
**铁律：逐条核对目标条目本身，不许用总分结案。** 已写进 `.claude/agents/red-team.md`。

**② 精确率能靠缩分母刷** —— 见第 4 节。**9/22 → 9/17，分子一个没动。**

**③ 枚举措辞的规则治不住模型 —— 它会发明新说法绕过**
案例：规则列了词表（「需微调」「不是…」「未体现…」），S067 发明「**非严格符合**」照给 88 分，规则完全落空。
**规则要给判据（能不能反复见到 / 主语是谁），不要给词表。**

**④ 拍脑袋估算高了 2-3 倍，差点去修一个不存在的病**
案例：估算 35 道候选输出 ≈4130 token「顶穿 4096」→ 实测只有 ~1800。
**更糟的是：如果照那个假设改了 maxTokens，真凶（30 秒超时）会继续存在，而我们会以为修好了。**

**⑤ 分批 / 单独问 = 换尺子**
重排的本质是**横向比较**——模型要在 35 道里判断哪道最贴合。分批后每批只看 8 道，**第 1 批的"最好"和第 4 批的"最好"用的不是同一把尺**，引入**我们没有指标能测到的偏差**。
同理否掉「补缺循环只单独问缺的那几道」。**替代：整批重问，最多 3 轮，尺子不变。**

**⑥ 改 prompt 有全局副作用，不是精准打击**
案例：只想治 4 条，实际 13 条里 5 条漂移且方向不受控（S051/S084 反而**涨**了，S084 金标=低 = 新增虚高）。全部 293 条候选：旧分 <40 段平均 **+5.1**、60-84 段 **-9.8**、≥85 段 **-8.1** —— **整张校准表在动**。
**改 prompt 必须预注册预期 + 逐条核对目标与非目标条目。**

**⑦ 三次都在 prompt 上找原因，第四次才想到查管道**
管道审计官原话。**下 "AI 判断力有问题" 的结论之前，先跑 `@pipeline-auditor`。** LOOP.md 已把它卡在"跑基线"和"@diagnostician"之间。

**⑧ `temperature: 0` 不代表确定性**
同代码、同输入、温度 0，三轮跑出三个不同的分（虚高率 17.4/21.7/20.0）。**别再假设"温度 0 所以可复现"。**

**⑨ 别把历史记录改成"正确"的数字**
要求"全仓库不再有 48/43 个观察点"是个偷懒的验收标准——`观察点审计.md`、`项目总览`、`交接文档06-04` 里的 43/44 **当时就是对的**。fix-engineer 拒绝改它们，理由是「**改历史记录会抹掉演进过程**」。它对了。**笔误订正和改写史料是两回事。**

**⑩ `| tee` 会吞掉退出码**
`bash regression-all.sh | tee log` 返回的是 tee 的退出码，FAIL 被伪装成 exit 0。用 `; exit ${PIPESTATUS[0]}`。

---

**⑪ 并档会白送一致率——比较前先确认两边的桶数一样多**
三档配置下 `TIER_SCORE.low=30 < SCORE_LOW=40` → 评估的「低」桶**物理不可达**，四档实为三档。
拿四档分母去比三档分母，**并档白送 +8.1~+10.1pp**，超过声称的全部涨幅。
**且 70% 的一致是白送的**：三轮恒 low 的有 103/148，模型只要把它们一路扔在底部就自动计入分子。
> **剔除白送、只看判别子集，③ 是三者最差（64.4% vs 73.7%）；high 档退 14pp。**
> **比较任何"率"之前，先问：两边的分母是同一个东西吗？**

**⑫ 发现差额却选择适应它，比没发现更糟**
见第 7 节原则 4。一句话：**"稳健于偏差"是把问题固化进代码的委婉说法。**

**⑬ 聊天里的口头数字不入档就不算数（"28"事件）**
产品方说「红线 3 原拍板值 **28** 作废」——我查遍 `BASELINE.json`（是 **12**）、查遍台账、查遍实测（三档下是 **22-25**），**28 查不到任何出处**。
它可能是记混了，也可能是某次对话里说过而没人记。**但结果一样：一个没进台账的数字，等于不存在。**
> **口头值不入档 = 不算数。** 这正是「每次合并 = 台账一条」和「无原话不标已决策」两条规则要防的东西——
> 而这次是**产品方自己的口头值**被这条规则挡住，不是 AI 的。规则对谁都一样。

**⑭ 「抗 A 侧漂移」不等于「抗一切漂移」——我今天栽在这**

我一整天说「召回精度扛过导出规模 40→100、管道大改、三轮抖动、金标改档」，把它当成红线设计的典范。
**红队一算：金标一改，30.4%→25.0%，跌 5.4pp。**
我错在：那些"扛过"的全是 **AI 侧**的变动——它当然不动，**因为它的分子分母全在金标侧**。
> **分母由金标定死的指标，金标一改它必动。这是同义反复，不是稳健性。**
**推广**：说一个指标"稳"之前，先问：**稳对什么？** 没有主语的"稳"是空话。

**⑮ 用会掩盖构成的聚合物，去论证构成没变**

我在提案里花一整节论证「极差 0 不等于零噪声，要做构成核对」，然后**贴出 6 个故事的集合**去证明召回率的分子三轮没变——
**而召回率的分子是 10 个条目**。故事级是条目级的投影，**它天然会掩盖条目级换构成**（S061 掉一条进一条，故事集合完全不动）。
**结论恰好是对的**（条目级复核后三轮确实相同），**但证据的粒度不足以支撑它**。
> **这正是我自己批判的那个错误形状，只是运气好没翻车。**
> 教训：**方法论要一以贯之地用在自己每一条上**——我用在了 6/7 号，没用在 1/3/5 号。

## 11. 停机规则（LOOP.md 有全文，这里给要点）

**只有四条必须停下问人：**
1. 用户能看到的东西变了（文案/画面/交互）
2. 要改金标 / 标准 / 指标定义 / 红线数值 / **产品不变式**
3. 红线之间**真**冲突（改动让某条红线 FAIL 且**无法两全**）
4. **动了零红线环节的 prompt**（`analysis.ts` / `practice.ts` / `restructure.ts`）——自动挂旗，不许静默合并

> 第 4 条是**哑铃**，不是解法。真正的解法是给这三个环节建 eval（大工程，未做）。在那之前用"改动必挂旗"换一点安全，代价是慢。
> **看不见的地方不许自己走。**

**分界线（拿不准时用这条判）：**
> **「我们不知道 X，却声称 X」= bug，自主修。**
> **「我们知道 X，但要不要告诉用户 / 怎么告诉」= 决策，问人。**

**特别澄清**：`@pipeline-auditor` 判"管道有问题"后，**停机的目的是让结论作废，不是让每个修法都问人**——修管道本身照常自主推进。

**为什么规则这么窄**：2026-07-16 一轮 loop 停了 7 次问人，**只有 1 次是真产品决策**。规则宽 = 看起来谨慎，实则失职——每次不必要的停机都在把判断责任推回给人，而人雇这套 loop 就是为了不用做这些判断。

## 13. `@recorder` 的五次顶回（都是对的，别绕过它）

`@recorder` 五次拒绝主会话的越权标注或指出其自相矛盾，**每次都对**：
1. 把没有拍板依据的条目标成「已决策」→ 顶回；
2. 擅自改他人已登记条目的状态 → 顶回；
3. 要求把「代码已修」直接记成「已解决」→ 顶回（**AI 报"我修好了"只是事实陈述，结案是人的决定**）。

它还自己给台账加了一个新状态「已作废（依据来自污染数据）」并注明**只有人能写**——防止后人把它当成 AI 可自行下的判定。

4. **从 039 的临时处理列交叉核对出 038 漏报一项改动** → 顶回。
   我在 039 里承认"我加了提醒"，在 038 的改动清单里没列这条——**同一个人写的两条记录互相矛盾，它只是把矛盾摆出来，不替我圆**。
   我漏它的理由，正是新规则要防的那种心态：「在我眼里那是顺手补的一句提醒，不是一次改动」。
   **新规立起来的第一轮，就抓到了立规则的人自己。**
5. **拒绝把「产品方裁决」四字转述标成「已决策」**（无原话不升格）→ 顶回。
   我回查产品方原文、补上逐字引用后才升格。**规则拦住的不是产品方的拍板，是主会话的转述失真。**
   它还用产品方原话「只报非零，不报量级」替换了我的措辞「不回答有没有埋没，不承诺量级」——**原话是可执行的判据，我的转述是个态度。**

> **它顶回来时通常是它对。**

## 15. 一句忠告

今天最贵的教训不是任何一个 bug，是这个：

> **我们花了两轮 prompt 修复、一次分诊、一份 13 条清单去调整 AI 的判断力，而真相是喂给它的数据本身就是错配的。**
> 三次都在 prompt 上找原因，第四次才想到查管道。

**接手时，先怀疑管道，再怀疑模型。**

晚上又学到第二条，它和第一条是同一个形状：

> **管道修好之后，我们量出了噪声地板 ±3~5pp —— 而我们一整天都在用 1.5pp 的容差争论 4pp 的差异。**
> 先怀疑管道，再怀疑模型；**但在这两者之前，先问一句"这个数字本身可信吗"。**

**顺序是：尺子 → 数据 → 模型。** 今天我们从最后一环开始，倒着走了一整天。
