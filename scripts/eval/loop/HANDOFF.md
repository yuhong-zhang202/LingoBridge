## 3. BASELINE v3 长什么样

**全部钉计数，不钉比率。** 理由：本项目两次栽在分母上（台账 019/044）；且比率的「±0」在量化指标上与「任何小于量子的容差」行为等价。

| # | 红线 | 值 | 分母归属 |
|---|---|---|---|
| 1 | 召回率命中数 | **≥10**（10/11 = 90.9%） | 🟢 金标定死 |
| 2 | 首屏可用故事数 | **≥6**（6/40 = 15.0%） | 🟢 |
| 3 | **金标未召回数** | **=0** | 🟡（守**上游**，见下） |
| 4 | noMatch | **=0** | 🟡 |
| 5 | **真丢数** | **null ⛔ 未钉** | — |
| 6 | **金标缺口项数** | **≤3** | 计数 |
| 断言 | 金标 11/40/148 + 候选 293/997 | 对不上直接 FAIL |

**观察指标（不作 PASS/FAIL）**：首屏精确率 / 虚高率 / 档位命中率（🔴 分母由 AI 控制）、金标高中标注占比（原召回精度）、埋没率（烟雾报警）。

**废除**：`noise_margin_pct: 1.5` 七条共用（萃取保留 1.5）｜`ranking_visible_zero_max: 12`｜`ranking_recall_precision_pct: 30.4`｜`ranking_firstscreen_precision_pct: 40.9`｜`ranking_inflation_rate_pct_max: 27.3`。

### 红线 3 为什么取代「召回精度」

召回精度 25.0% = 分子 37（高11+中26）、分母 148，**全是金标常数，换任何模型跑都是 25.0%**。实测对照：

| 场景 | 召回精度 | 未召回数 |
|---|---|---|
| 踢 1 条金标「低」出召回（刷分） | 25.00% → **25.17% 涨，PASS** | 0 → 1 **FAIL** |
| 漏召回 1 条金标「高」 | 25.00% → 24.49%，**跌 0.51pp，小于任何容差** | 0 → 1 **FAIL** |

⚠️ **但它守的是【上游】，在重排回路里恒真**：三轮候选集逐位恒等（293/293/293）且「金标 ⊆ 候选」= True → 有效 **n=1**。**别把它的「三轮恒 0」当稳定性证据——那正是它给召回精度定的罪。**

## 5. 🔴 重排噪声地板 —— 一切"涨跌"先过这道

**同代码、同输入、`temperature: 0`，三轮跑出三个不同的分。** 重排噪声是萃取的 3–5 倍。

```
🟢 分母由金标定死 → 极差 0        🔴 分母由 AI 控制 → 极差 0(假)~11.3pp
```
> **LOOP.md 原则 2 在这里被独立验证了两次**：它当初从「分母缩水能刷分」推出来，**没想到它同时决定指标稳不稳**。同一条原则，两个独立的理由。

### ⚠️ 「三轮没漂」这个结论，2026-07-17 被推翻过一次——推翻的是提出它的人自己

主会话测了全局均值（22.89 / 24.26 / 22.76，轮1→轮3 配对比较 **−0.12**），**公开宣布「漂移假设被证伪」**。红队指出该驳回**欠功效**，主会话复算属实：

```
金标=中  n=26   59.0 → 54.1   Δ = -4.88   ← 跌破60就成真丢
金标=低  n=60   29.7 → 32.5   Δ = +2.87   ← 冒过60就成缺口/虚高
金标全体 n=148  34.0 → 34.2   Δ = +0.23   ← 主会话当初用的就是这个
```
**两个方向相反的真实运动，在全局均值里正好抵消。** 这正是不变式 9 警告的「**把骗换成空**」的形状。
⚠️ **红队的诚实限定必须一并读**：置换检验 **p=0.127 / 0.053，均不显著——红队没有证明漂移存在**。它证明的是「**主会话用来驳回漂移的那个统计量，结构上就看不见这个最该防的模式**」。
> **结论：漂移既未被证明，也未被排除。** 这是「聚合数字会骗人」的**第七次**，**而这次骗的是提出它的人自己**。

## 6. 挖出的 bug（最容易丢的上下文）

**它们是同一种病**：`??` 静默塞默认值 + 不校验 + 不留证。
**铁律：凡是跨越 AI 边界的数据，必须校验、必须留证、不许用 `??` 兜底。`??` 在 AI 边界上不是容错，是把错误伪装成正常值。**

前 8 个见 git history（`matching.ts` join key 错位 / `extraction.ts` 白名单 / `rankQuestions` catch 吞证据 / 测试靠 bug 作弊 …）。**2026-07-17 新增两个，都在回归守卫自己身上（台账 064）**：

```python
# regression-all.sh 旧实现（已修）
all((c.get('relevanceScore') or 100) < 40 for c in st['candidates'])
```
1. **`< 40` 是旧可见线** —— `SCORE_LOW` 已在 `dd418d5` 删除，尺子 v3 定 `<60 不展示`。
2. **`or 100`** —— 不变式 #2 明令禁止的 `?? 100`，且 **Python 的 `or` 比 `??` 更糟：`score = 0` 会变成 100**（实测三轮有 10/6/11 条 0 分候选）。

**后果**：三轮真实 26/25/27 被算成 **14/19/16**。且按守卫自己的算法 **14 > `ranking_visible_zero_max: 12` → 这条红线今天就已经是 FAIL，只是没人跑它。**
> **为什么长期没被发现**：HANDOFF 曾称「`?? 100` 全清」——**那次清的是 TypeScript，grep `?? 100` 抓不到 Python 里的 `or 100`**。
> **教训：「全清了」这句话的作用域，往往是你 grep 的那个作用域。**

## 7. 红线设计四原则（LOOP.md 有全文，这里给实证）

1. **精确率天然可用"少预测"刷分，必须配召回率。** 实测：40.9% → 52.9% 看着涨 12 点，逐条核对是 **9/22 → 9/17，命中的就是同样那 9 条，连集合都一样**。
2. **分母必须用金标定死的量。** 实测：导出从 40 故事变 100，**12.5% 被算成 5.0%，报了个假 FAIL**。
3. **一条红线只防一个方向，成对的红线才防得住取舍。** 设计新红线时先问：**想刷这条线最省事的做法是什么？那个做法会伤到什么？把那个"什么"也变成红线。**
4. **参数与现实对不上时，解释差额，禁止用"自适应/稳健于偏差"绕过。**
   > **声明让位给实测的每一处，都是一个潜伏 bug。**
   > 实操细则：**挪任何阈值前先看分数直方图，线放凑整谷底。**（模型凑整点是 10/5/25/15/20/**40**/35——旧线 40 踩在密集峰 5.02%，新线 60 落谷底 1.10%，低 4.6 倍。）

## 10. 踩过的坑（新窗口最容易重犯）

**① 聚合数字会骗人 —— 总分回到基线 ≠ 修好了。** 铁律：**逐条核对目标条目本身，不许用总分结案。**
**② 精确率能靠缩分母刷** —— 9/22 → 9/17，分子一个没动。
**③ 枚举措辞的规则治不住模型** —— 它会发明新说法绕过。**规则要给判据，不要给词表。**
**④ 拍脑袋估算高了 2-3 倍，差点去修一个不存在的病。**
**⑤ 分批 / 单独问 = 换尺子。** 重排的本质是横向比较。
**⑥ 改 prompt 有全局副作用**，整张校准表在动。
**⑦ 三次都在 prompt 上找原因，第四次才想到查管道。** **先怀疑管道，再怀疑模型。**
**⑧ `temperature: 0` 不代表确定性。**
**⑨ 别把历史记录改成"正确"的数字** —— **笔误订正和改写史料是两回事。**
**⑩ `| tee` 会吞掉退出码 —— 而这条坑记了半天的【解法本身是错的】（2026-07-17 实测）**

原文写的是「用 `; exit ${PIPESTATUS[0]}`」。**`PIPESTATUS` 是 bashism。本机 `$SHELL = /bin/zsh`**，zsh 里是小写 `pipestatus`、**且下标从 1 起**：
```
zsh:   PIPESTATUS[0]=[]      pipestatus[1]=[1]     ← 大写的那个根本不存在
bash:  PIPESTATUS[0]=[1]

zsh 里跑 HANDOFF 教的写法:  bash x.sh | tee log; exit ${PIPESTATUS[0]}   → 退出码 0（期望 7）
改用:                       bash x.sh | tee log; exit ${pipestatus[1]}   → 退出码 7 ✅
```
`exit` 收到**空参数** → 退出码取上一条命令（tee）的 0 → **FAIL 照样伪装成成功。这条坑的解药，自己得了这条坑的病。**
> 由 `@baseline-engineer` 2026-07-17 在范围外撞到并报告（它自己的岗位说明书第 6 条就写着那个错解法），主会话复算属实。
> **这是坑⑱「推断不是实测」的第三例**：写下来的解法，没人在本机试过。
>
> **正确写法（两条都行，第二条更稳）**：
> ```bash
> # A. 显式指定 bash 跑（PIPESTATUS 才存在）
> bash -c 'bash x.sh | tee log; exit ${PIPESTATUS[0]}'
> # B. 根本别用管道 —— 先落盘再看（跨 shell 通用，推荐）
> bash x.sh > log 2>&1; rc=$?; cat log; exit $rc
> ```
**⑪ 并档会白送一致率** —— **比较任何"率"之前，先问：两边的分母是同一个东西吗？**
**⑫ 发现差额却选择适应它，比没发现更糟。**
**⑬ 聊天里的口头数字不入档就不算数（"28"事件）** —— **规则对谁都一样，那次挡的是产品方自己的口头值。**
**⑭ 「抗 A 侧漂移」不等于「抗一切漂移」** —— **说一个指标"稳"之前，先问：稳对什么？没有主语的"稳"是空话。**
**⑮ 用会掩盖构成的聚合物，去论证构成没变** —— 结论恰好对，**证据的粒度不足以支撑它**。

### 2026-07-17 深夜新增四条，全部来自同一个形状

**⑯ 把【构造性恒真】当【实测稳定性】**
`金标未召回数` 三轮恒 0，主会话写进 BASELINE 当稳定性证据。红队一查：三轮候选集**逐位恒等**（293/293/293）且「金标 ⊆ 候选」= True——**它在重排回路里恒真，有效 n=1 不是 3**。

**⑰ 认知标准要一以贯之——不一致时，看它往哪个方向偏**
主会话援引「n=3」三次：底座「n=3 不足以认定结构」→不设线（松）｜真丢上限「n=3 最坏值」→钉6（松）｜缺口上限同（松）。

> **自查法：把你的每一条论证列出来，看它们指向的方向是不是全都一样。**

**⑱ 「推断」不是「实测」——这套 loop 最核心的宣言，从来没人试过**
LOOP.md 说 guard-golden「hook 直接物理拒绝」。

## 11. 停机规则（LOOP.md 有全文）

**只有四条必须停下问人：**
1. 用户能看到的东西变了（文案/画面/交互）
2. 要改金标 / 标准 / 指标定义 / 红线数值 / **产品不变式**
3. 红线之间**真**冲突（**能两全就不是冲突，是还没想够**）
4. **动了零红线环节的 prompt**（`analysis.ts` / `practice.ts` / `restructure.ts`）——自动挂旗

**分界线（拿不准时用这条判）：**
> **「我们不知道 X，却声称 X」= bug，自主修。**
> **「我们知道 X，但要不要告诉用户 / 怎么告诉」= 决策，问人。**

**为什么规则这么窄**：2026-07-16 一轮 loop 停了 7 次问人，**只有 1 次是真产品决策**。规则宽 = 看起来谨慎，实则失职——**每次不必要的停机都在把判断责任推回给人，而人雇这套 loop 就是为了不用做这些判断。**

## 14. 一句忠告

**顺序是：尺子 → 数据 → 模型。**

2026-07-16 学到第一条：**先怀疑管道，再怀疑模型**——我们花了两轮 prompt 修复去调 AI 的判断力，而真相是喂给它的数据本身就是错配的。
2026-07-16 晚上第二条：**在这两者之前，先问一句"这个数字本身可信吗"**——我们用 1.5pp 的容差争论 4pp 的差异，争了一整天。
**2026-07-17 第三条，它比前两条更难受：**

> **尺子修好之后，最后一个没被怀疑的东西，是拿着尺子的那个人。**
>
> 这一轮所有的错都不在代码里：把构造常数当实测、n=3 三次援引全部倒向更松、用一个看不见该模式的统计量宣布该模式不存在、以及**推断门禁能拦而从没试过**。
> **四个错，没有一个是自查出来的，全是红队抓的。**
> 而红队自己也在推断（它说 guard-golden 拦不住 Bash——对，但它没跑过）。
>
> **能跑的东西不要推。自己的每一条论证，都要用批判别人的那把尺子量一遍。**
