# Anki 卡背 · 分点式形态 v0.3（2026-07-24）

> **取代 v0.2 的"整段范文"形态**。产品方 2026-07-24 拍板：整段长英文与"轻盈快节奏刷卡"矛盾（背诵压迫感），卡背改**分点式**。
> 本文承载新形态的拍板结论 + 生成/金标规范 + 旧资产去留 + 后端影响。设计出处：metric-designer 重设计提案（2026-07-24）。整段设计见 `方案-Anki题卡-v0.1.md`(v0.2)，其 §7 档位/band 部分已作废、仅存档。

## 1. 卡片结构（拍板）
一张卡背 = **一个「点」的有序数组**。每个点：
```
{ focusIndex, title(免审·复用), desc(免审·复用), exampleEn(需审·新生成) }
```
- **title + desc**：直接取自现有 `question_analyses.analysis.focusPoints[i]`（`{标题(4–8字), 中文说明(1–2句)}`）。**不重新生成、不进金标**——因它是 storyless 静态分析、客观对题思路、与具体用户语料无关（免审前提成立）。
- **exampleEn**：针对该点、基于**用户中文语料**新生成的一句短英文口语例句。**唯一需生成、需审的产物**。
- **part1 → 2 点**（起手/收尾）；**part2 → 3 点**（背景/讲清重点/补感受）——跟随现有 focusPoints 写死点数。

## 2. 三项核心拍板（2026-07-24）
1. **不分档、砍 band 落地**：短例句不再按用户目标分调地道度，统一"自然达标口语"一个目标（≈原 B 档/6.0）。连带 **`TIER_SPLIT`/`bandToTier`/`resolveTargetBand`/profiles 目标分列/注册弹窗全部从关键路径移除**——顺手解掉"band 落地被注册流程阻塞"的死结。理由：单句尺度上整段的 A↔B 4 维区分有 3 维坍缩、档位一致率测不稳；产品取向本反对"更地道"。
2. **part2「讲清重点」点 = 1 句（≤22 词）**：与其他点一样压成一句，最轻盈、忠料暴露面最小。（放弃"2–3 句讲透"的候选。）
3. **part1（有语料）统一分点式（2 点）**：一套卡片结构/生成契约/金标，不维护两种格式。

## 3. 例句生成规范
- **长度**：每点约 1 句，part1 两点 + part2 三点均 8–22 词。
- **口语化**（沿用整段铁律）：可缩写、松弛；禁长难句/书面连接词/作文腔。
- **忠料红线（核心，分点式最易踩）**——分点式把每点变"格子"、模型本能想**填满格子**，这正是整段探针唯一反复的坑（编时间/地点/人物）：
  - **事实层**：例句事实（地点/人名/数字/时间/事件）只能来自语料。**语料没讲够 → 例句说笼统甚至省掉，绝不为填满该点而编**。原则：**「点可以轻，不能编」**。
  - **强度层**：不把语料事实渲染成语料没有的比喻/情绪强度。
- **格式**：复用 §2 sanitizer（纯英文/无 markdown/无破折号/无元信息词/词数上限/非空），单句版更简单。
- **生成架构**（采纳建议）：一次 LLM 调用输出 **JSON 点数组**（`callLLMJson` 范式），各点互见避免重复，省 token。

## 4. 金标（只审例句）
| 维度 | 类型 | 说明 |
|---|---|---|
| D1a 忠料·事实层 | 人工 | **核心红线**，分点式最易踩；建议设硬闸但基线后定 |
| D1b 忠料·强度层 | 人工 | 有无语料没有的比喻/情绪放大 |
| D2 对点贴合 | 人工 | **分点式新增**：这句是否确在说它那个点、没跑偏/没跟别点重复 |
| D3 口语化 / D4 无中式 | 人工 | |
| 硬规则 | 机器 | 纯英文/无 md/无破折号/无泄漏/词数/非空 |
- 双人盲判 D1a/D2/D4 报 κ（仿萃取金标）；**先跑基线、后定红线、不预设及格线**。
- 体量约整段的 1/3–1/2（无长度/句法/话语标记分档维度；忠料范围小到一句话）。

## 6. 后端影响（待 fix-engineer）
1. **生成器 `anki-answer.ts`**：整段→逐点；输出纯文本→**JSON 点数组**（转 `callLLMJson`）；入参带 focusPoints；**`tier` 入参移除**（不分档）。
2. **卡背存储**：`anki_cards.generated_answer`(单 text) → 存**点数组**（JSON 列 or 新表）；`edited_answer` 逐点编辑 vs 整体——**待定（§7 待办 4）**；波及已建 `get_anki_cards` RPC / `PATCH editedAnswer` 端点。
3. **prompt 同源守卫**：整段 prompt 整个重写、建新同源锚点；清理 C 档惰性段。
4. **成本按新形态跑真数重估**（多短句 vs 整段，别外推）。

## 8. part3 形态（metric-designer 补设计，2026-07-24）
- **结构**：part3 也是 3 点（立场 / 理由 / 延伸），有现成 `generatePart3Analysis`（pregen 的 `PART3_SYSTEM_PROMPT`）产出 focusPoints，可复用当标题+中文解释（免审）。
- **例句来源 = 通用示范论据句**（generic exemplar）：part3 无用户语料，例句是"这个论点可以怎么用一句话论证/举例"的**范例**，**不基于用户语料**。
- **金标维度与 part1/2 不同**：part3 例句**不审"忠料事实层"**（无语料真相源），改审 **①论据贴合论点 ②常识不离谱（不编虚假数据/荒谬断言）③口语化 ④无中式**。
- ⚠️ **part3 净增 AI 生成量**：整段时代 part3 从不生成（generated_answer 恒 null），现在要生成论据例句 → 成本重估必须把 part3 卡数算进去。

## 9. 数据结构（拍板契约）
`anki_cards.generated_answer`：整段 string → **JSON 数组 `[{idx, en}]`**，与 focusPoints 一一对齐；渲染时前端拼 `focusPoints[idx].title/desc`（免审）+ `en[idx]`（需审）。**标题+解释与例句物理分离 = 金标只审 en[]**。

## 10. part3 存储：静态化、不破不变式（metric-designer 补设计修正）
part3 例句 = **通用示范论据句**（不基于用户语料），故**随 focusPoints 一起预生成、静态存入 `question_analyses.analysis`**（focusPoint 从 `{title,desc}` 扩为 `{title,desc,example?}`）——**不进 `anki_cards.generated_answer`、不走 drain、不 per-user**。
- ✅ 于是 part3 的「`corpus_id`/`generated_answer` 恒 null」不变式（0030 触发器）**原封不动、无需松绑、无需回 red-team**（撤销早先"要松绑"的判断）。
- part3 卡背整体纯静态；天然无 band（pregen 时没有 per-user 目标分输入）→ 进一步佐证 band 落地对卡背全不需要。
- part3 focusPoints 已有现成框架（`pregen-analyses.ts` 的 `generatePart3Analysis`/`PART3_SYSTEM_PROMPT` 产出 立场/理由/延伸 3 点），只需每点补一句英文 `example`。
- ⚠️ part3 是**净增 AI 生成量**（整段时代 part3 从不生成），但走 pregen 静态生成、不走 drain；成本重估要把 part3 题数算进。
