# LingoBridge 内测评估方案 v1

> 性质：流程规范。agent 可提案修订，人批准后生效（介于不变式与权威文档之间）。
> 位置：`docs/内测评估方案.md`。前置阅读：`PRODUCT_INVARIANTS.md`、`匹配链路-权威文档.md`、`LOOP.md`。
> 定稿：2026-07-16，基于三档标签改造后的仪器状态。

## 〇、一句话原则

**合成数据回答"仪器准不准"，内测数据回答"产品好不好用"。**
内测本身就是第一次真实评估：每条真实故事都是一次测量——前提是留证开着。

## 一、目的与非目标

**目的**
1. 测出真实分布下的萃取 / 召回 / 重排表现（合成 eval 只给出均匀分布下的平均分，见台账 006）
2. 回答 006：真实用户的题材 / 观察点分布长什么样
3. 回答 005：供给缺口在真实分布下到底疼不疼
4. 产出金标 v2 的原料（真实故事）

**非目标**
- 不为让合成指标好看做任何设计妥协
- 不用内测数据实时调 prompt。内测期间**仪器冻结**，改动只处理 P0（见第四节）；
  常规优化等金标 v2 落地后走原 loop 流程

## 三、三层评估体系（按成本从低到高）

### L1 · 计数层——第一天就有数，零标注成本

| 指标 | 回答什么 | 口径要点 |
|---|---|---|
| 观察点分布 | 006（头号要看的数） | 每故事 primary 计数；与合成集的均匀分布对照 |
| noMatch 率 / 假空率 | 兜底压力、005 的真实疼痛度 | 分母 = 真实故事数 |
| 首屏选题率 | 高档质量的行为代理 | 选了首屏题的故事 ÷ 有首屏题的故事 |
| 折叠展开率 / 折叠选题率 | 中档的真实价值 | 展开且选中 ÷ 展开 |
| 练习完成率（分档位） | 台账 001"原样能答"的直接行为测量 | 完成 ÷ 开始，high / mid 分开算 |
| 空态后动作 | 空态成本 | 重讲故事 / 切雅思模式 / 流失，三分计数 |
| parse fail、超时、降级率 | 仪器健康 | 生产单请求口径（勿与 eval 并发口径混比，见台账 025） |

**分母铁律（原则 2 的内测版）**：所有比率的分母用系统外的量（故事数、会话数、用户数），
不用模型输出控制的量。

### L2 · 分诊层——每周一轮，人是唯一裁决者

**矛盾样本捞取规则**（行为与档位打架的）：
- AI 判 high、用户开练但短时间内放弃或中途换故事
- AI 判 low（被隐藏）后，用户重讲了一个语义近似的故事
- noMatch / 假空之后用户直接流失

**处理方式**：
- 内测早期（< 50 故事/周）：**人全量读，不抽样**。抽样是数据多到读不完时才需要的东西。
- 数据多了之后：`@diagnostician` 按既有门槛预分诊，人只看被标出的。
- **行为是分诊触发器，不是自动标注**——用户放弃可能只是累了，不能直接判档位错。

**判例机制（S074 教训，本方案的核心增补）**：
- 已证实："AI 稳定分歧（R≥3 全一致）"这个信号**依赖输出结构**——同一模型同一故事同一题，
  换个输出结构立场就翻（S074：旧结构稳定 mid 并引用规则，新结构稳定 high 并绕开规则）。
  它可以继续做触发器之一，但**不再是充分依据**。
- 结构无关的两个主依据：
  1. **结构自洽审计**：同题、同观察点、同结构，金标却不同档（先例：台账 004）——纯客观比对
  2. **人类判例**：每次人裁决的边界案例，写成判例进权威文档（先例：S074"习惯 vs 某一次"裁决）
- 判例累积就是 rubric 的活文档：新标注员（人或 AI 分诊）先读判例再干活。

### L3 · 金标 v2——内测 2~4 周后启动

- **抽样框**：真实故事，按 观察点 × 档位 × 空态 分层
- **标注对象**：restructure 的**输出**（与生产喂给萃取的输入对齐），
  不是 ASR 原文，也不是用户打字原文——标注对象和生产输入不一致，测出的就不是生产准确率
- **标注流程**：照抄萃取金标已验证的那套——双人独立标注、算一致率、分歧讨论定稿、
  元数据留 source / annotator / revisedAt / revisionNote。**重排金标同样双人**（v1 的欠账不再欠）
- **顺序铁律（这次不许倒）**：
  ① 量标注者一致率（人的噪声地板）→ ② 量模型噪声地板（R=3）→ ③ 按两个地板定容差 → ④ 最后钉红线
- **规模**：v2 目标 ≥ 60 个真实故事（预计足够覆盖真实高频观察点；长尾点等 v3）

## 四、内测期间的停机线（P0，出现即修，不等周节奏）

- 萃取产出白名单外的观察点并显示给用户（防线已建，此处为监控确认）
- 用户可见的判词错位（reason 显示的是别的题的理由）
- 重排整体降级率异常（生产口径，阈值待第一周基数出来后定）
- 任何隐私事件（日志泄露、脱敏遗漏）

## 五、周节奏

```
周一  L1 计数汇总出报告
周二  L2 矛盾样本清单 → 人裁决 → 判例入权威文档 → @recorder 记台账
随时  P0 停机线触发即处理
```
改 prompt / 阈值 / 指标定义，仍走 LOOP.md 停机规则，内测不豁免。

## 六、退出标准（内测评估阶段完成的定义）

- L1 各指标有 ≥ 4 周稳定读数
- 金标 v2 定稿，且人与模型两个噪声地板都已量
- 新红线体系钉在 v2 上（数值 + 逐条容差）

达成后，loop 从"仪器维护 + 分诊"模式切回"优化循环"模式——这一次，对着一把可信的尺子。

## 附：本方案继承的教训清单（来源：2026-07-16 交接文档 + 后续实验）

1. 尺子 → 数据 → 模型，顺序不许倒（红线最后钉）
2. 分母必须用系统外 / 金标定死的量
3. 聚合数字会骗人：一切改动逐条核对，配对比较优先于点值比较
4. temperature 0 不代表确定性；一切"涨跌"先过噪声地板
5. 金标必须双人 + 一致率 + 分歧留痕（v1 单人单遍的欠账不再欠）
6. "AI 稳定分歧"依赖输出结构，不作为金标复审的充分依据
7. 仪器改动使基线作废：每换一次尺子，旧数字只留档不比较
