# Anki 题卡功能 · 功能规格 v0.1

> 产品方 × cowork 对话梳理，2026-07-23。本文件为**设计基准**，供 `metric-designer` / `Plan` / `ux-reviewer` 出方案、`red-team` 审查。规格如有改动以本文件为准。

## 0. 一句话
把雅思口语题做成 Anki 间隔重复卡片：正面题目、背面（有语料 → AI 按档位生成的英文回答 / 无语料 → 题目分析）；相同语料的题排在一起，让用户"刷卡建立眼熟 + 直观看到一段语料能覆盖哪些题"。

## 1. 目标与价值
- 雅思题海逐题练记不住；Anki 间隔重复建立"眼熟/覆盖感"，多刷几轮对大部分题有印象。
- 相同语料的卡相邻 → 落地产品核心「一料多题 / 信息复用」。

## 2. 卡片内容
- **正面**：英文口语题（part2 展示 cue card 题面）。**翻面 = 点击**。
- **题目分析**（通用、静态、按题预生成存库）有双重角色：
  - **展示**：无语料 part1/part2 卡、以及**所有 part3 卡**的背面，直接显示题目分析。
  - **生成输入**：part1/part2 有语料时，用「题目分析 + 题目类型 + 语料」生成英文回答。
- **背面矩阵**：

| 卡 | 条件 | 背面显示 | 可编辑 |
|---|---|---|---|
| part1 | 有语料 | **仅英文回答**（生成，简短） | ✅ |
| part1 | 无语料 | 题目分析 | ❌ |
| part2 | 有语料 | **仅英文回答**（生成，较长） | ✅ |
| part2 | 无语料 | 题目分析 | ❌ |
| part3 | 其 part2 有语料 | 题目分析（**不生成回答**） | ✅（用户自己写/改） |
| part3 | 其 part2 无语料 | 题目分析 | ❌ |

- **规则**：可编辑 ⇔ 有语料可依（part3 借它 part2 的语料状态）；**AI 生成回答只发生在 part1/part2 有语料两种**，part3 从不生成。
- **编辑**：改的是卡上英文表达，持久化在卡上，**不回写语料库**；中文语料稳定、卡背不联动；**无重新生成按钮**。

## 3. AI 生成（卡背英文回答）
- **输入**：题目分析 + 题目类型(part) + 中文语料 → 英文回答（part1 短 / part2 长）。
- **档位**：目标分粗分 2–3 档（低 → 更简 / 高 → 略丰富），目标"眼熟好记"，不追求命中精确分。
  - 目标分是**综合分**，口语常达不到；按"达标口语下限"取向（简单反而好记）。
  - 切点由 `metric-designer` 提案 + 人审 + 参考公开 IELTS band descriptors 资料。
- 语料为中文、语料梳理环节不产英文 → 卡背英文**全新生成**。
- **时机**：存对子时**后台生成、成功才写库**（用户此刻在匹配/整理页、不等卡；去素材库时已就绪，无"生成中"态）。快速连存内部**排队限流**；生成失败**后台重试**。
- **题目分析**：通用静态，一次性**批量预生成存库**，直接调用（省钱免延迟）。

## 4. 筛选 / 排序 / 分组
- **两维筛选**：`{全部题卡 | 已回答题卡} × {part1 | part2}`（"已回答" = 有语料绑定）。
  - 全部 + part1 = 所有 part1（有 + 无语料）
  - 全部 + part2 = 所有 part2 **及其 part3**
  - 已回答 + part2 = 有语料 part2 + 其 part3
- **排序**：有语料卡（同一批语料相邻，段内按题库匹配页顺序）→ 无语料卡；**多段语料的批次之间按语料创建时间**。
- **part2 组** = 1×part2 + N×part3，part3 紧跟其 part2（`questions.parent_card_id` 反查）；**part3 不单独 tab**。
- **无语料卡范围** = **当季**（`questions.season`）全库未匹配的题。

## 5. 间隔重复 SRS（艾宾浩斯）
- 每卡带记忆状态，按遗忘曲线调度下次出现。
- **手势**：**左滑 = 不熟悉**（更快再现）/ **右滑 = 已收悉**（间隔拉长）；桌面**左右两按钮** + **键盘 ←/→**（← 不熟 / → 熟）。
- 暂不设"每日新卡上限"；绑/删语料致背面变化时 SRS 进度**保留**（题没变）。

## 6. 存对子（= 生成卡）入口 —— 移动端 + 桌面端都要
- **语料模式**：匹配页出候选题 → 移动端**右滑存**（类似 Gmail 右滑归档动效）/ 桌面**题目详情卡右上角图标**；整理确认页**无**存按钮。
- **雅思模式**：题已预选、**无匹配页** → **整理确认页语料组件右上角图标**存。
- 两模式的题都能产卡；**一题一语料**：某题已被匹配、再存别的语料 → 弹窗"是否更换语料" + 可看当前语料详情；暂不做误滑撤销。

## 7. 素材库 / 管理
- Anki 速览 = 素材库**新建独立入口**（IA 需重排）。
- 素材库可看已存**对子**；删对子 → 该卡背面**回退题目分析**、可再次结对。

## 8. 其他
- 注册后弹窗**强制设目标分**（所有新用户；目前无老用户），说明用于卡片内容生成。

## 9. 数据模型雏形（供 Plan 细化）
- **卡表**：`(user_id, question_id)` 唯一 + `corpus_id`(可空绑定) + `generated_answer` + `edited_answer` + SRS 字段(due / interval / ease / reps) + 时间戳。
  - "有无语料" / "全部 vs 已回答" / 背面是分析还是回答，**全从这一行的 `corpus_id` 空不空推导**，不是两套卡；绑/删语料只改这一行，SRS 状态随行保留。
- **题目分析表**：按题预生成静态分析（question_id → 分析）。
- part3 ↔ part2 复用现有 `questions.parent_card_id`。

## 10. 实施顺序
- **设计阶段**：数据模型 / AI 金标 / 产品逻辑 / UI 四面**并行**出方案。
- **实施阶段**：**后端先行**（数据模型 + 生成流水线 + SRS 调度 + 预生成题目分析），前端后接（可先拿 mock 契约搭骨架）。理由：前端强依赖后端数据契约与生成产物；AI 生成是最大风险，先跑通去风险。

## 11. 留到设计/实施阶段解决（不阻塞规格）
档位切点具体值 · 卡背生成金标（防中式英语、part1 短 / part2 长、档位适配）· SRS 具体间隔表 · 生成失败重试策略 · 素材库 IA 版式 / 右滑与卡叠视觉 · 预生成题目分析的批量任务（覆盖当季全库、内容质量）。
