# 方案：经营看板重设计（2026-08-04 实施稿）

ux-reviewer 三轮评审（整体重评 + 反馈待办 + 优先级重排与用户区扩充）的合并定稿，产品方已确认按此实施，改完本地验收后再推 main。反馈待办（S2/S4 的读写与组件）**已实施完毕**（commit `018d2c8`，迁移 0055 已上生产），本文档覆盖其余步骤。

产品方拍板的优先级：**有无 bug → 有无反馈 → 注册人数 → 活跃程度 → 留存率 → 成本明细及其他后移**。

两个已按建议执行的决定：
- 回访口径用宽口径（当日有任意 flow_events 即算回来），口径小字必须写明「回来 = 有任意使用记录（含仅浏览）」，不许省。
- 「离开页分布」暂缓：埋点满 14 天且周活跃 ≥ 5 人再上，现在只放占位说明行。

## 一、目标态整页骨架（桌面）

```
LINGOBRIDGE
经营看板

┌ 今日结论条 ────────────────────────────────────────────┐
│ ● 今天有 2 件事要处理                                    │
│   [反馈 1 条未处理 · 查看↓] [计费失败 3 次(语音转写) · 查看↓] │
└───────────────────────────────────────────────────────┘

┌─紫·今日新增注册─┐ ┌─橙·今日核心活跃─┐ ┌─绿·今日练习场次─┐
│   2            │ │   3            │ │   5            │
└────────────────┘ └────────────────┘ └────────────────┘

明细（可展开）                          [7天|14天|30天]

▸ 有新反馈吗    1 条未处理 · 历史 12 条            [全时段]
▸ 用户走到哪    注册→激活→留存 · 页面活跃           [近7天]
▸ 出事了吗      本期失败 3 次 · 该我们修 1          [近7天]
▸ 钱花在哪      今日 ¥3.2 · 本月 ¥41.5             [近7天]
▸ 看板自己还准吗 埋点 14 事件全通                    [近7天]
```

折叠区新顺序：**有新反馈吗 → 用户走到哪 → 出事了吗 → 钱花在哪 → 看板自己还准吗**。刻意不做「有事时物理位置提前」的动态排序（单人日读用户会形成位置记忆，跳变破坏可预期性）；有事的引导由结论条锚点承担。

各区收起态 summary 补常驻结论数字（`CollapsibleSection` 的 `subtitle` 传动态串）：见骨架图。

## 二、S1 今日结论条（新组件 `TodayVerdictBar.tsx`）

**「事」的判定来源，全部今日东八区口径、复用现有字段**：

| 判定 | 来源 | 呈现 |
|---|---|---|
| 计费失败 | `todayFailuresTotal > 0` | 红 chip「计费失败 N 次，卡在{topPhase} · 查看」→ 锚点到①区失败明细表 |
| 新反馈 | `feedback.unhandledCount > 0`（返回体已备好） | `text-brand-primary-dark` chip「反馈 N 条未处理 · 查看」→ 锚点到反馈区并展开（反馈是要处理不是坏了，不用红） |
| 成本 | 现有 `costWarn` 判定 | 黄 chip「今日 ¥x · 超 7 日均 2 倍」→ 锚点到钱区 |
| 速度 | `todayStatus.slowestPhase.p90 > latencyWarnMs` | 黄 chip「{环节}变慢 P90 xs」→ 锚点到深挖区耗时面板 |

🔴 **flow_events 的「该我们修」桶刻意不进结论条**：它是区间口径，与「今日」混用是误报温床（ux 三轮里最重要的口径决定之一）。它继续只在①区展示。

- 外壳：白卡 rounded-16 细边；有系统故障时整条 `bg-error/[0.06] border-error/20`；仅反馈/成本/慢时用 warning 同结构透明度。禁新色值。
- 圆点 + 文字双承载状态；主句 `text-[0.9375rem] font-semibold`；每件事是 `min-h-[44px]` 链接式按钮。
- 全绿态一行：「● 今天不用处理什么 · 无失败 · 成本正常 ¥2.41 · 无新反馈」。
- 锚点跳转：`scrollIntoView` + 置对应 `details.open` + **落点 `tabIndex={-1}` + `focus()`**（不能只滚动）。
- `<section aria-label>` 复述整句结论。

## 三、S3 Hero 三卡 + 折叠区重排

**Hero 从四卡改等宽三卡：今日新增注册 / 今日核心活跃 / 今日练习场次**（改 `HeroMetrics.tsx`）。

- 容器 `grid grid-cols-1 md:grid-cols-3 gap-3 mb-5`；卡壳沿用现款。
- 顶部 3px 彩条与参与度趋势三线同色编码：注册 `#9A7DB8`、活跃 `#D4875A`、练习 `#7BA699`。
- 主数字统一 `text-[2.5rem] font-bold tabular-nums leading-none`（三卡等重，无跨列主卡）。
- 副行照搬现有实现：注册卡两态口径文案（`newRegistrationsPending` 降级照搬）；活跃卡匿名副行（0 隐藏）；练习卡「新练 x · 复练 y」双色点。

**撤出两卡的职责去向（逐条钉死不悬空）**：

| 撤出项 | 新落点 |
|---|---|
| 计费失败卡 | 结论条第一 chip + ①区 defaultOpen 数据驱动 |
| 失败卡副行「空录音 N 次」 | ①区摘要行（上次误报来源，这条信息不许丢） |
| ③卡常驻口径边界文字（OUT_OF_SCOPE_NOTE） | 移入①区 AI 结局分布块顶部 |
| 成本卡 | 结论条黄灯 chip + 钱区 summary 常驻「今日 ¥x · 本月 ¥y」 |

**①区 defaultOpen 改数据驱动的实施注意**：`<details>` 的 open 是一次性初始属性。用反馈组件已验证的模式：**惰性 useState 只算一次初始值**（open 属性终身不变、React diff 恒等、用户手动开合天然保留）。代价（数据到达前不知道有没有失败、首帧先收起）可接受：结论条会点名。

## 四、S5 用户区扩充（「用户走到哪」，第一个数据折叠区）

### 区内结构（自上而下）

1. **增长漏斗**（现有，不动）
2. **新注册的人还回来吗**（新组件 `CohortReturnTable.tsx`）
3. **哪些页面被用得多**（新组件 `PageActivityList.tsx`）
4. 离开页分布占位行（暂缓项）
5. **参与度趋势**（现有，不动）

同时：**删掉本区与 Hero 重复的「今日新增注册」「今日匿名活跃」两张小卡；假空率小卡挪去①区**（它是采集故障性质）。

### 「新注册的人还回来吗」

口径：近 7 天按注册日分组（profiles 真注册、剔内部账户），回访 = 该人当日有任意 flow_events（东八区日界、剔 is_qa 与内部账户）。**只显人数分子/分母，不显任何百分比。**

```
┌ 新注册的人还回来吗 · 近 7 天注册分组 ──────────────┐
│ 注册日    注册      次日回来      至今回来           │
│ 8/2       2 人      1/2           2/2              │
│ 8/1       1 人      0/1           0/1              │
│ (无注册日子合并一行:「其余 4 天无新注册」)           │
│ 口径: 回来 = 当日有任意使用记录（含仅浏览）·东八区;  │
│ 未满次日的行显「待满 1 天」，不显 0                  │
└──────────────────────────────────────────────────┘
```

- 「次日回来」在注册日+1 未过完时显「待满 1 天」（muted），绝不显 0/2 冒充流失。
- 数据帮手 `fetchCohortReturns`（`lib/db/dashboard-metrics.ts`）：profiles 近 8 天注册行 × flow_events 近 8 天 user_id×日去重，内存 join，走既有 fetchAllRows 分页模式。

### 「哪些页面被用得多」

口径：窗口内 `page.view` 按 route 聚合：打开次数（横条，`bg-brand-accent/70`，与环节成本条同范式）+ **「用过的人」user_id 去重副列**；剔 is_qa 与内部账户。

```
│ 页面浏览埋点自 08-03 上线,现仅积累 N 天,方向参考、别当结论  ← 常驻至满 7 天
│ 页面        打开次数              用过的人
│ 练习对话    ████████████ 34       3 人
│ 首页        ██ 6 (此行系统性偏低*)  2 人
│ 默认列前 8，其余收进「展开全部 N 个页面」
│ * 打开次数=页面加载次数,刷新/多开重复计,不是访问人数;
│   首页对未建会话的新访客不上报,该行偏低,新访客量看注册数
```

- **防 UV 误读是本块第一要求**：列名「打开次数」；「用过的人」并列副列；首页行**内联**标注偏低（不放脚注）。
- 数据不足降级：窗口 0 行 → PendingPlaceholder「页面浏览埋点 2026-08-03 上线，本窗口暂无数据」；有数但不足 7 天 → 顶部常驻事实陈述行（muted，非告警色）。
- 数据帮手 `fetchPageViewStats`：flow_events 取 `event='page.view'` 窗口行，route 聚合次数 + 人数去重。
- 离开页占位行（PendingPlaceholder 虚线框）：「离开页分布：数据积累中，页面埋点满 14 天后此处自动显示（首页缺口会把部分离开错记到前一页，届时一并标注）」。

## 五、S6 ①区收敛 + 告警四件套

### ①区内部结构

```
▾ 出事了吗
│ 本期 3 次计费失败 · 该我们修 1 · 最慢环节 题目重排 P90 27.1s   ← 新增摘要行
│ [每日失败柱图]（保留）
│ [AI 结局分布]（保留不动；顶部接收 Hero③卡撤下来的口径边界文字）
│ [哪个环节在失败]（保留；无失败时不渲染，也删掉「本期各环节无失败」空占位卡）
│ [失败明细表]  ← 仅本期失败 > 0 时渲染，删空表
│ [假空率小卡]  ← 从用户区搬来
│ ▸ 各环节耗时（点开：分布/趋势） ← 降为 details 默认收起，摘要提进顶部摘要行
```

### 告警四件套（S4，针对静音误报教训的呈现规范）

1. **`failedLogs` 带影响者**：route 给失败行加服务端截断的 user_id 前 8 位（完整 id 不出接口），`RecentCallsTable` 失败视图加「用户」列（匿名标出）。
2. **分类置信度可见**：`error_kind` 来源分实测与 `classifyErrorKindFromLog` 事后推断两种，推断出的分类挂中性「推断」小角标。红色只给确认项：实测系统故障亮红；推断的红 + 角标；原因未记录一律灰。
3. **error_message 全文行内展开**：替代 hover title（触屏/键盘不可达）。行内展开区 `bg-cream-subtle rounded-[12px]` 等宽字体，展示完整 error_code / error_message（可选中复制）/ logId / 东八区时间；展开按钮 `aria-expanded`、命中区 44px。
4. **「该我们修」格下钻**：归属三格 ours > 0 时格内附最近一条明细（环节中文名 + result 代码 + 时间）+「查看失败明细」锚点；并补一句互证文案：「若下方明细里的类型是空录音/网络，说明归类可能有误，以明细行的错误类型为准」。

1. `RecentCallsTable` / `EnumChip` 的 title 承载信息改行内展开或文字副行。
2. 9px 文字（失败表 error_code、预算线 label、失败柱标数）统一提到 10px 起；失败表副字建议 `text-[0.625rem]`。
3. `PhaseLatencyPanel` 表头 `text-v2-text-muted/70` 去掉 `/70`（叠透明度后必不达 AA）。
4. 自绘按钮统一补 `focus-visible:ring-2 ring-brand-primary/40`。
5. `CostTrendChart` 的 Area 补 `isAnimationActive={false}`（与同页其他图对齐）。
