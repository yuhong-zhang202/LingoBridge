# 内测邮箱白名单 —— 启用与拆除说明

> ⚠️ **这是一项【内测临时措施】，内测结束后请按本文第三节拆除。**
> 建立于 2026-07-19（commit `40f24f1`）。台账见 `scripts/eval/loop/DISCUSSION_LOG.md` 条目 113。

---

## 一、它是什么 / 为什么这么做

**作用**：只有提前录入名单的邮箱能**注册账号**；名单外的邮箱注册时会被明确拒绝。

**匿名试用不受影响**（产品方 2026-07-19 拍板）：没登录的人照样能试用一圈，只是没法注册、数据存不下来。所以白名单挡的是「长期占用」，不是「完全不让碰」。

**为什么闸做在数据库里**（两条反直觉的事实决定的）：
1. **登录/注册是浏览器直连 Supabase**，不经过我们任何后端接口，也没有 middleware ⇒ 在前端或 API 里挡都拦不住（anon key 是公开的，能直接绕过）。
2. **本项目「注册」其实是 `updateUser` 把邮箱绑到已存在的匿名账号上**（不是 `signUp`）⇒ Supabase 的 Auth Hook 根本不会触发，用不了。

所以准入只能挡在 `auth.users` 表的**数据库触发器**上。

## 二、日常使用

### 加人（即时生效）
Supabase 控制台 → **Table Editor** → `beta_allowlist` → Insert row：

| 字段 | 填什么 |
|---|---|
| `email` | 内测者邮箱（大小写随意，比对时两边都转小写） |
| `note` | 备注，如「内测第一批」（可空） |

### 删人
删掉对应行即可。⚠️ **删人最多 60 秒后才在 API 层完全生效**（有 60 秒缓存），数据库触发器侧是即时的。

### 首次启用的顺序（重要）
1. 在 SQL Editor 跑 `supabase/migrations/0023_beta_allowlist.sql`（幂等，可重跑）。
2. **立刻插入产品方自己的邮箱**。
3. 再插其他内测者。

> **为什么顺序不能反**：表为空时视为「白名单未启用」（防呆），全部放行；**插入第一行的瞬间白名单就激活了**。若第一行不是你自己，你会被挡在所有 AI 功能之外（能登录，但一点就 403）。

### 三重防呆（不会把自己锁死）
- **表为空** = 白名单未启用，全放行
- **存在 `email = '*'` 的行** = 停用（见第三节）
- **API 层查表失败时放行**（fail-open）——主闸在数据库触发器，兜底层故障不会导致全站不可用

## 三、⭐ 内测结束后怎么停用 / 拆除

### A. 临时停用（首选，零部署、零改代码、一秒可回滚）

往 `beta_allowlist` 表**插一行**：

| email | note |
|---|---|
| `*` | 停用白名单 |

**立即生效**：触发器和 API 兜底层同时视为「未启用」，任何邮箱都能注册登录。
**回滚**：删掉这一行，拦截立刻恢复。

> ✅ **功能在这一步就已经完全恢复开放了。** 下面的 B 只是清理技术债，不着急、也不影响使用。

### B. 彻底拆除（闲时做，注意顺序）

**第 1 步 · 清数据库**（SQL Editor 执行；这段也抄在 migration 文件末尾注释里）：
```sql
drop trigger if exists enforce_beta_allowlist_trg on auth.users;
drop function if exists public.enforce_beta_allowlist();
drop table if exists public.beta_allowlist;
```

**第 2 步 · 清代码**（三处都打了 `【临时措施】` 注释标记，搜这四个字即可定位）：
- `src/lib/api-auth.ts` —— 删「内测邮箱白名单兜底闸」整段（`loadAllowlist` + `assertAllowlisted`）+ `authUser()` 里那行 `await assertAllowlisted(...)` 调用 + `logErr` import（若无其他用处）
- `src/lib/auth.ts` —— 删「内测邮箱白名单文案映射」整段（`isAllowlistDenied`）+ 注册/登录两处分支
- 删测试文件 `src/lib/__tests__/api-auth-allowlist.test.ts`
- 删 migration 文件 `supabase/migrations/0023_beta_allowlist.sql`

> ⚠️ **顺序提醒**：代码删除应与 drop table **同批或在它之后**。若先 drop table 而代码还在查，虽有 fail-open 兜底不会崩站，但会持续往日志里刷错误。

**已注册用户完全不受影响** —— 本方案只拦写入、不改 `auth.users` 里的任何数据，拆除后内测期注册的账号照常使用。
