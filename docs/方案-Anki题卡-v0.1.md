## 1. 数据模型（迁移 0030–0032）
- **`anki_cards`(0030)**：`(user_id,question_id)` 唯一 + `corpus_id`(可空=真相源) + `generated_answer` + `edited_answer` + Leitner(`box/due_at/last_reviewed_at`)。RLS own-rows。
- **派生模型**（避免两套卡）：有无语料/已回答/背面内容/可编辑 **全从 `corpus_id` 空不空 + part + parent_card_id 推导**。part3 卡 `corpus_id` 恒 null、`generated_answer` 恒 null，可编辑性经 parent part2 卡推导、用户自填存 `edited_answer`。
- **稀疏表 + 懒物化**（关键）："全部题卡" = `questions(当季) LEFT JOIN anki_cards`；无卡行的题按"默认卡"(背面=分析,box1,due=now)渲染；**首次 SRS 手势/存对子才 INSERT 行** → 几百题不预插、SRS 随行保留。
- **`question_analyses`(0031)**：预生成静态分析(含 part3)，question_id 主键 + season + analysis jsonb，公开可读。
- **`anki_generation_jobs`(0030 同批)**：生成任务队列（serverless fire-forget 会丢，必须落表）；status/attempts/退避。

## 2. 生成流水线（后台生成、成功才写库）
存对子 → 同步 upsert 卡行(绑 corpus_id) + 入队；`generated_answer` 先 null、**成功才回填**（用户此刻在别处、不等卡）。**drain 处理器**（香港 PaaS 常驻/cron，`FOR UPDATE SKIP LOCKED`，按 user 串行+全局限并发=天然限流，失败指数退避重试）。生成器 `anki-answer.ts`：分析+part+中文语料+档位→英文回答(part1短/part2长)，`bandToTier()` 隔离切点（**2 档单阈值常量 `TIER_SPLIT`**，见 §7）。沿用同意闸/计次/记账范式。
- **出口 sanitizer（v0.2 新增，格式达标正解）**：生成文本落库前过一道确定性后处理——破折号 `—/–`→逗号或句号（**限两侧至少一侧非数字**，避免误伤 `10–11 p.m.` 这类数字区间）、strip markdown 星号/井号/反引号/下划线、去掉整段包裹引号。理由：探针两轮实测证明 H2(markdown)/H3(破折号) 靠 prompt 禁令收不住（H3 仅 3/24），且在 prompt 里点名禁某句会 anchoring 反噬；格式是机械问题，用后处理断言≈100%，把 go/no-go 从打不赢的 prompt 仗里解放出来。⚠️ **scope 仅格式**：sanitizer 让格式≈100% 只指"格式合规"、**不代表生成质量达标**（格式从不是 go/no-go 卡点），勿被下游误读；且破折号→标点可能造逗号粘连（如 `early—I need`→`early, I need`），落地时抽样确认"照着念"不别扭。

## 3. 预生成题目分析
`scripts/pregen-analyses.ts`（照 `import-season.ts`：service-role、dry-run 默认、幂等续跑）。遍历当季全库(**含 part3**)→ part-aware 分析。⚠️ 现 `generateAnalysis` prompt 写死排除 part3，须新增 part3 分支。

## 4. SRS
复用 `srs.ts`：左滑不熟→box1、右滑熟→box+1(封顶 60 天)。绑/删语料只改 `corpus_id`、不 touch SRS → 进度保留。⚠️ **大 deck**：当季几百张首刷全 `due=now` 一次涌来，不设上限会淹；建议前端分批取 + 后端预留"每日软上限"过滤位（加个过滤即可、表结构不改）。

## 5. 查询（RPC 0032 `get_anki_cards(scope, part)`）
`questions(当季,part) LEFT JOIN cards` + season 过滤 + `scope='answered'` 过滤 corpus_id + 排序(有语料批次→无语料；批次间按 `corpus.created_at`；段内近似匹配页序) + part2 带其 part3 成组。逐像素还原匹配页序需给 `corpus_question_matches` 加 `display_index`(可选增强)。

## 6. 存对子 + 端点
`POST /api/anki/cards`(存/绑, 409 冲突) · `PUT .../corpus`(换语料) · `DELETE .../corpus`(删对子,回退分析) · `GET /api/anki/cards?scope=&part=`(RPC) · `POST .../review{remembered}`(SRS+懒物化) · `PATCH .../{editedAnswer}` · `POST /api/anki/generate/drain`(内部/cron) · `scripts/pregen-analyses.ts`。
⚠️ **换语料边界**：换语料 = 新语料源，旧 `generated_answer` 必错配 → 技术上应清空+重排队生成（与"禁手动重生成按钮"不矛盾）——**待产品裁定**。

## 7. AI 金标（metric-designer）——**v0.2 档位定为 2 档**
- **档位 = 2 档（A 基础 / B 自然）**，取消原 C 档。[产品方 2026-07-23 拍板]
  - **主论据（与样本量无关、稳）**：C 档"更地道"的增量方向与本功能"眼熟好记 / 达标口语下限 / 简单反而好记"取向相反——习语密度高的范本对照念的考生更难念难记、考场用错语境反暴露背的。**本功能取向上就不要 C 档**，这条不依赖探针样本量。
  - **次论据（探针信号，n=2 弱、暂缓待验）**：两轮探针仅 2 条 Part2 输入，C 档在无引语抓手题（B2）上转文学隐喻+编造（三红线全踩、~band8），有抓手题（B1）尚可——**疑似题材依赖**。但 **n=2 不足以断言"C 档全库注定塌"**，此为**暂缓、非技术否决**；真要做 C 须换 2–3 个题型复判后再验（red-team 复审 v0.2 要求，见 §11 冻结门 / §13b）。
  - **降 2 档的代价多为伪代价**：目标是**综合分**、中国考生口语普遍是短板，综合分 7.5 的用户口语达标下限通常落 6–6.5、B 档即够；真正亏到的仅"综合分高且口语也强"的少数人，而他们最不需要照念卡背。
- **切点（可落地初值，金标基线后回填）**：目标综合分 T → 达标口语下限 **S = T − 0.5**（稳妥偏上）→ 档位。单一切点常量 `TIER_SPLIT` 划在 **T 6.0/6.5** 之间：**T ≤ 6.0 → A 档**（范本 band 5.0–5.5，CEFR B1）；**T ≥ 6.5 → B 档**（范本 band 6.0–7.0 中枢 6.5，CEFR B2，默认档，主流 6.5 目标用户落此）。⚠️ 切点具体值"先跑基线再定、不预设"。
- **A↔B 靠 4 个题材无关、可机器近似量测的维度稳定区分**（也是 A↔B 值得保、B↔C 不值得的根据）：① 句法复杂度（past perfect 计数、从句/总句比例：A 简单句为主 ≤1–2 处 past perfect，B 简单+复杂句混用）；② 词汇 CEFR 层级（A 主体 A2–B1 高频词，B 允 B2 词汇与自然搭配）；③ 话语标记密度（A 平实，B honestly/actually/and yeah 自然过渡）；④ 长度（仅 Part2：A 120–150 词，B 160–200 词）。
- **分层测法**：硬规则(机器) / 档位(人**二分类**判档→档位一致率，只判档不判 band 绝对分) / 软质量(人工各维通过率)。生成无唯一解，不设"整体感觉良好率"。
- **质量维度 D1–D7**：忠于语料/对题/档位复杂度/part长度/口语化/无中式英语/格式无泄漏。**D1 忠料拆「事实层 / 强度层」双列**（对齐生成 prompt 铁律 3——事实层=新增地点/人名/数字/时间/事件，强度层=文学隐喻/情绪放大；这是探针里唯一反复的失败维度，必须单列可追）。
- **标注模板列**：`样本ID | part | 目标档 | 中文语料 | 生成英文 | 盲判档位(A/B) | 忠料(事实层) | 忠料(强度层) | 对题 | 口语化 | 中式 | 长度合规(机器带入) | 备注/分歧`；前列+生成文本预填，盲判列人工填。
- **指标 M1–M5 + 先基线后红线**：生成成功率/硬规则/档位一致率/软质量/稳定性；不预设及格线。
- **金标集**（2 档缩约）：part(2) × 档(2) × 题材(8) ≈ 32 组合 × 3 次 ≈ **96 样本**（原 3 档 ≈144，降约 1/3）；双人盲判报一致率（Cohen's κ，先判"人能否稳定判档"再谈机器达标）。删掉的正是 B↔C 那条最窄缝。⚠️ **删 C 槽位缓执行**：补双人盲判确认「A↔B 真稳 且 C 真不可分」之前，金标**保留能重测 C 的槽位**（哪怕先不投产 C），别把 n=2 结论焊进测量装置、将来想要 C 时连探坑器都一起删了（red-team 复审 v0.2）。
- **band 绝对分**：纯文本 band 读数偏乐观，绝对分锚定需**真人复述录音复判**，留金标深验阶段，不进本轮档位一致率。
- ✅ **低档可行性已被探针证实**（原"最大风险"未兑现）：A 档修订后实测降到 band 5.5、短句可复现、**无中式**——"简单 vs 不中式打架"的担忧未发生。

## 8. UI/UX（ux-reviewer）
- 命名 **「题卡」**(不露 Anki)；扩展现有 FlashCard 范式。
- **素材库 IA**：现已有"词组闪卡"入口，题卡是第二套 → 「今日复习」区**并排双中卡(平级)** 或 **题卡升满宽 Hero(主推)**——产品优先级决策，两解。
- **卡片**：正面英文题(part2 带 cue bullets)；背面英文回答(带档位小标)或分析；点击翻面；编辑态原地转 textarea(锁滑动防误触)。
- **SRS 复习**：复用 `/review` 骨架；左滑不熟(暖底)/右滑熟(绿底)拖动实时反馈；桌面左右按钮+键盘；卡叠剩余感；完成态。
- **筛选**：{全部|已回答}×{part1|part2} 两组 Chip(注意 44px 命中区)。
- **分组"同批语料相邻"**：卡顶彩色 chip(`PHRASE_CHIP_STYLES` 循环色)同色=同语料；段内"第2/3题(同语料)"；建议素材库入口先列表浏览再进滑动。
- **存对子**：匹配页移动右滑(Gmail式,绿底Bookmark)/桌面详情卡图标；雅思整理确认页图标；换语料弹窗(对比当前vs新语料)；已存态防重复。
- **空态**：EmptyState 分完全无卡/某筛选无卡(轻量)。
- ⚠️ **a11y 欠账**：现 FlashCard/lib-deck-float 未做 `prefers-reduced-motion`，题卡必须补；手势外必留按钮+键盘；44px 命中区；图标 aria-label。

## 13. 探针结论（go/no-go，2026-07-23）
