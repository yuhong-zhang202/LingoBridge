## P0 · 扩量前必须处理

### P0-1　故事删不掉：97% 的语料没有删除入口，与隐私承诺冲突

**事实核准**（这条曾被误读，先说清楚）：素材库的删除按钮**是真删语料**（走 `deleteCorpus`，不是只解绑对子）。问题在**列表的取数范围**：它只列「已存成题卡对子的语料」。

| 生产实测 | |
|---|---|
| 语料总数 | 189 |
| 绑了对子、能在列表里看到并删掉 | 5 |
| **无对子、列表里根本不出现** | **184（97.4%）** |

用户讲完故事、匹配完就走（没存题卡），这条语料从此不出现在任何界面，也删不掉。而隐私说明写着「你的故事由你自己掌控：可随时自行删除」。

**处置**：把 `MyStoriesTab`（205 行，能列全部语料，代码还在、只是无人引用）接回素材库。附带解掉「已攒下 N 条」把看不见的语料算进去、点进去却是空的矛盾。

**工作量**：半天。**卡在**：无，可直接做。

### P0-2　全局 AI 预算熔断 + 匿名额度收紧

**背景澄清**：392 个匿名账号里 **324 个（83%）零埋点事件**，是 P0 已修的那个服务端 bug 造的垃圾号，不是攻击。真讲过故事的 24 个，烧过钱的 41 个。**目前无任何攻击痕迹。**

但防线确实是空的：`DAILY_BUDGET_CNY = 20` 只是看板参照线，不是执行闸；匿名号可无限创建，日额度按账号计。

**处置**（产品方已确认不开验证码，故走代码层）：
1. **全局日预算熔断**：今日 AI 总花费超阈值时，对匿名会话一律拒绝新调用，注册用户不拦。这是唯一与攻击手段无关的止损。
2. **匿名转写额度 25 → 5**：试用一遍产品 5 次足够，25 是最贵链路上的空头支票，单号价值直接降 80%。

**工作量**：一天。**卡在**：熔断阈值需要产品方给一个数（建议日预算的 3 倍）。

### P0-3　时区日界不统一（四份审计中三份独立报告）

额度按 **UTC 日界**重置（香港时间**早上 8 点**才恢复），而看板全线东八区，文案写「明天会自动恢复」。用户凌晨 0 点半打开仍被拦。

实测每天有 **20% 到 40%** 的流量落在这个错位窗口（08-03 有 79 次调用、08-02 有 43 次）。

同类问题在月额度上更糟：客户端用**设备时区**、服务端用**容器时区**，每月 1 日 00:00 到 08:00 这 8 小时，客户端已进新月、服务端还在上月，会出现「本月额度已用完」配「0 / 10」进度条、还给一个点了必然再被拦的按钮。

**处置**：额度日界与月界统一到东八区，与看板 RPC 同款写法。**注意迁移当天的计数连续性**。

**工作量**：半天 + 一次迁移。**卡在**：切换当天会有一批用户计数重新分桶，需产品方确认可接受。

### P0-4　三条已发生过的事故，今天零测试守卫（变异实证）

架构审计把三处代码改回它们的历史 bug 形态，跑全量 790 个测试：

| 变异 | 结果 |
|---|---|
| `levelForScore(undefined)` 返回 `'high'`（曾导致降级时全部候选被标高匹配写库） | **790 全绿** |
| `assertCorpusOwner` 改空实现（7 条路由的跨用户越权唯一防线） | **790 全绿** |
| `questionFace` 回退（曾系统性造成 Part2 虚高） | **790 全绿** |

对照组：`contentHashOf` 去掉 level → 7 个红；`echoMatches` 恒真 → 8 个红。**不是测试整体弱，是这三条恰好在真空里，而它们偏偏是三条已经发生过一次的事故。**

**处置**：三个都是纯函数，各写 20 行测试。`levelForScore` 需先 export 或抽独立模块。

**工作量**：半天。**卡在**：无。**这是所有项里性价比最高的一条**（扩量期必然重构，这三条是最可能被无声碰坏的）。

## P1 · 扩量期间会咬人

### P1-1　看板两个聚合器静默截断

`fetchCohortReturns` / `fetchPageViewStats` 手写分页，跑满 100 页（5 万行）直接退出，**没有标志位、没有日志**，把不完整数据交给聚合。同项目里 `fetchAllRows` 做对了（返回 `truncated` 并一路带到 UI）。

后果是**恒定方向的偏低**（分页按时间升序，被截掉的永远是最新那批），而这正是扩量期唯一用来判断"有没有留住人"的仪表。

估算触顶点约 150 到 250 日活（审计自评这个数字只能当数量级看）。

**处置**：改调 `fetchAllRows` 并把 `truncated` 带到 UI；`fetchCohortReturns` 补 event 过滤能砍一个量级。**工作量**：半天。

### P1-2　转码并发闸的理由与位置错配

并发数压到 2 的注释理由是"ffmpeg 转码吃 CPU、超过核数会互抢"，而另一段注释明说"闸只包住豆包调用，转码绝不能圈进来"。**两句各自都对，叠起来是错的**：转码并发实际无上限，ASR 吞吐白白砍半。

50 个并发上传同时进 ffmpeg，2 核被 25 倍超卖，全站所有接口一起变慢。

**处置**：给转码一个独立并发闸（上限=核数），ASR 闸放回 4（豆包限额 5）。**工作量**：半天。**卡在**：属架构取舍，建议先确认 Zeabur 实例规格。

### P1-3　匹配无服务端去重，3.1% 重复整跑

生产实测：131 个跑过匹配的语料里 4 个跑了两趟，其中 3 次确认是并发而非重试（两趟相隔 0.25 秒 / 6.8 秒 / 14.5 秒，均小于单趟耗时）。快照读与写之间没有锁。

单价不高（约 ¥0.0085/次），但两趟同时跑意味着两倍并发与两倍长请求占用，扩量后是放大器。

**处置**：服务端按 corpusId 做进程内单飞（`ensureSession` 已有同款范式）。**工作量**：半天。

### P1-4　安全响应头全缺，删号按钮可被点击劫持

生产站实测没有 `X-Frame-Options` / CSP `frame-ancestors` / `X-Content-Type-Options` / `Referrer-Policy` / HSTS，且暴露 `x-powered-by`。

攻击方式：把设置页放进透明 iframe，诱导已登录用户点两下触发删号。**不是 CSRF**（写接口都要 Bearer 头，跨站表单设不了），是 clickjacking。

**处置**：`next.config.mjs` 加 `headers()`，六个头一次配齐。**⚠️ `Permissions-Policy` 必须保留 `microphone=(self)`，否则录音直接坏，改完必须真机验证录音。** 完整 CSP 另案（有两处内联 script 需 nonce 改造）。

**工作量**：半小时 + 真机验证。

### P1-5　`review_events` 漏出删号链路

该表有 `user_id` 但**无外键**（93 行数据），而删号路由的显式删除清单里没有它，`admin.deleteUser` 的级联也兜不到。结果：注销用户的 uuid 永久留库，再无机制会清。

这正是删号路由自己在注释里判定为"不可接受"的那种残留。

**处置**：删除清单加一行 + 补 FK 做第二道闸。**工作量**：十分钟。

### P1-6　跨境存储的同意版本敞口

已按产品方指示把「你的数据存放在哪里」加进隐私详情页（设置页可达），**但刻意没有 bump 版本号**。

代价必须记账：`BETA_PRIVACY_VERSION` 同时是同意记录落库的 `consent_version`，不 bump 意味着**已签的 125 名用户，其同意记录对应的仍是不含跨境披露的 v3**。PIPL 第 39 条要求向境外提供个人信息须取得单独同意。

**处置**：闭合只需把版本改成 4（老用户下次进来重签一次，缓存 key 含版本号会自然失效）。**重签成本随用户数线性上涨。**

**卡在**：产品方决定。建议扩量前做完。
