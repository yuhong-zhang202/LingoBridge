# 产品不变式（PRODUCT INVARIANTS）

> **这份文件是规范性的，不是描述性的。**
> 它写的不是"现在怎么工作"（那是 `docs/匹配链路-权威文档.md` 的事），而是**"什么不许变"**。
>
> **和金标同级：只有人能改。** 任何 subagent 无权写入本文件（`guard-golden.sh` 已保护）。
>
> **怎么用**：`@pm-reviewer` 每次合并前逐条对照。**任一条动摇 → 挂旗停机**，不许自行判断"这个改动应该没关系"。
>
> 每条都标注了来源。**没有来源的条目不许加进来**——不变式必须能追溯到一次真实的拍板。

## 一、匹配与展示

### 1. 「高匹配」= 这道题能原样用语料回答，不是"最接近的题"
`[来源：2026-07-16 产品方拍板 / 台账 001]`

这条决定了一切下游口径：首屏可用率的诚实值、要不要收紧重排、`GroupHeader label="高匹配"` 那行文案改不改。

**推论**：当池子里没有能原样答的题时，正确行为是**首屏诚实地空着**，不是把最不烂的一条捧上去标「高匹配」。
> 用供给稀缺赦免虚高，等于承认"没好题时可以骗用户"。

### 2. 用户看到的每道题必须有分数依据。无分数 → 不展示、不落库、不标任何档
`[来源：2026-07-16 产品方拍板 / 台账 018、021；分界线来自台账 020]`

**这条是「我们不知道 X 却声称 X」在匹配链路上的具体化。**

- **不落库**：`route.ts` 的 `levelForScore` 遇 `score === undefined` 必须返回 `null`。
  历史教训：曾是 `score ?? 100`，重排降级时把全部候选以 `match_level='high'` **永久写进库**，下游任何读这张表的功能都继承这个谎。
- **不展示 / 不标档**：`page.tsx` 不得用 `?? 100` 把未打分候选算进 `highGroup`。
- ⚠️ **同一字段不得在不同文件有不同默认值**。历史教训：`matching.ts` 用 `?? -1`（排序沉底）而 `page.tsx` 用 `?? 100`（分组算高匹配），同一批候选**既是「高匹配」又排在最后**，UI 自相矛盾。

### 3. 首屏 = 高匹配区。中 / 低匹配折叠
`[来源：既有设计，2026-07-16 确认]`

**推论（必须一起满足）**：首屏为空时，用户必须落在一个**有出口的画面**上（`NoMatchView`），而不是"标题说有 N 道、屏幕上零张卡"的破损页。
> 已知缺陷（台账 002，已拍板必修）：`highGroup=0 且 midGroup>0` 时三个空态判断全部落空 → 破损页。仅移动端（`MatchingDesktop.tsx` 三组无条件渲染，无此洞）。

### 4. topic_only 题只经首页泛题池 → 带 qid → 直达分析，不走召回
`[来源：既有设计，2026-07-16 确认]`

> ⚠️ **本条目前不由代码保证，靠数据约定维持。** `getQuestionsByObservation`（`src/lib/db/questions.ts:99-113`）查的是 `question_observation_links` 表，**没有任何 `topic_only` 过滤**。只要有人给一道 topic_only 题加了 link 行，它立刻会被召回，没有任何东西会拦。
> **建议**：加一条校验或测试把这条约定钉死。在那之前，改动召回逻辑或题目映射时必须人工确认这条没被破坏。

## 二、单一事实源

### 5. 观察点体系唯一真源 = `extraction.ts` 的 `SYSTEM_PROMPT`
`[来源：2026-07-16 fix-engineer 提案 + 产品方采纳 / 台账 017]`

DB（`observation_points` 表）、邻接表（`observation-adjacency.ts`）、文档都是它的**下游**。

**为什么是 prompt 而不是 DB**：白名单校验要回答的不是「这个 code 存不存在」，而是**「模型有没有照我们给它的清单选」**——那份清单就是 SYSTEM_PROMPT 本身。拿 DB 校验会在漂移时否掉 prompt 合法提供的 code（误杀真答案）。改 prompt 即改校验，由构造保证一致。

**实测（2026-07-16）**：prompt=49 / DB=49 / 邻接表=49，键集完全相同，邻接值也全部指向真实 code，**零漂移**。
> 文档里的「48 个」（`ENGINEERING.md:169`）和「43 个观察点」（`src/lib/db/observation-points.ts:3,35`）**都是错的**，正确是 49。

### 6. 题面唯一构造入口 = `questionFace()`
`[来源：2026-07-16 题面残缺教训]`

任何新消费方**不得自行拼接**题面。Part 2 的 cue card 必须带完整题面（含 "You should say" 约束 bullet）——自行拼接会漏掉约束，导致模型/用户看到的题面残缺。

当前消费方：`src/services/matching.ts:177`、`scripts/eval/run-ranking.ts:207`。**两者共用同一函数，这是它们能对齐的唯一原因。**

## 三、考卷与题库

### 7. 金标只能由人写
`[来源：loop 设计原则；hook 强制]`

任何 subagent 无权写 `scripts/eval/golden/`。`guard-golden.sh` 物理拦截，不靠自觉。

**同级保护**：`BASELINE.json`（红线数值）、`run-ranking.ts` / `run-extraction.ts` / `run-ranking-score.ts`（评估脚本与指标定义）、`scripts/eval/loop/specs/`、本文件。

> **"这条金标标错了"也不许自己改**，只能进台账等裁决。先例：S018/S044 曾因"AI 稳定不同意金标"翻案——是人的判断比 AI 准，但那也是**人**下的判断。

### 8. 产品承诺「当季真题」—— 题库不得编题
`[来源：2026-07-16 / 台账 007]`

题库是固定的一季真题（`scripts/data/question-observation-remap.v2.json` 的 `basis`：雅思口语题库 2026 年 1-4 月 Version3 逐题人工审查），前端文案承诺「当季真题」（`MatchingMobile.tsx:115`）。

**题不能编。** 所以"补题库"实质是"要不要放弃'当季'承诺"——雅思整体有那些题，但不在这一季。**这是产品决策，不是工程决策。**

## 四、核心定位

### 9. 把用户真实的生活故事转化为口语素材
`[来源：产品定位 / 2026-07-16 明确]`

**任何让"用户讲了故事却得不到可练的题"的改动，都是在削弱定位，必须上报。**

这条是第 1 条的对冲，两者必须一起读：
- 第 1 条防的是**骗**（给一道他答不了的题，还标「高匹配」）
- 第 9 条防的是**空**（把首屏优化成一片诚实的荒地）

> **红线设计原则三的由来**：只守"精确率↑ + 虚高率↓"，最省事的刷分法是把所有候选压到阈值以下——两条都变好，用户看到空屏。所以必须有"首屏可用率不许跌"对冲。**2026-07-16 实测拦住过一次真实的收紧刷分。**

**判断句**：一个改动如果同时让"骗"和"空"都变少，它是真改善；如果只是把"骗"换成"空"，它是在挪问题，必须上报，由人定这笔交易划不划算。
